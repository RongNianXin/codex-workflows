# TRB-007 · HTTP 400：对话过长

| 字段 | 内容 |
| --- | --- |
| 错误码 | `400` |
| 典型正文 | `This conversation has grown too long to continue` |
| 根因范围 | 当前链路拒绝继续处理该长会话；限制层待确认 |
| 当前状态 | 有可用恢复流程，不能修复原会话 |

## 识别与排查

必须以实际失败事件中的 HTTP 状态、错误类型和完整正文为准，不能只凭用户转述的“400”。先保存当前工作区、已写文件、任务状态和最后一个可确认断点；本地 JSONL 大小、压缩次数不是服务端请求长度的统一阈值。

确认正文明确表示会话过长后，不再向原失败会话试探。检查是否已经产生工具副作用或外部写入；没有证据时保持现场，不重放未知状态的操作。

## 最小恢复

1. 在授权范围内建立新任务或新分支。
2. 只读取已完成历史、状态索引和交接快照，恢复最后可确认断点。
3. 先发送无副作用的只读检查，确认新任务能生成回复。
4. 验收回复内容、任务状态和工作区差异后再继续业务。

原任务保留为证据，不删除、不强行压缩、不反复重试。若错误正文不是明确的会话过长，转总索引按其他签名分流。

## 边界

这不是 `429` 限流，也不是工具调用配对错误。若正文同时包含字段缺失、分页谱系或代理转换信息，按对应文件处理；不能因为同为 `400` 就合并根因。
