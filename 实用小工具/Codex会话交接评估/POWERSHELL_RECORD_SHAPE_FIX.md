# JSON 字段顺序漏计修复与截断记录提案

## 修复结果

原分析器通过文本中前两个 `type` 判断记录类别，合法 JSON 字段重排会让 100 Token 被静默漏计为 0。现按对象层级读取外层 `type`、`payload.type`、回合 ID 和时间戳，并复用已解析对象。字段移到 4,096 字符之后或存在嵌套同名字段时，也不再依赖文本出现顺序。兼容 PowerShell 返回字符串或日期对象的时间戳。

只修复合法记录识别；累计 Token 基线、回合合并、分段拒绝条件和现有截断记录统计策略均未放宽。脚本保留 UTF-8 BOM，以支持 Windows PowerShell 5.1 读取中文源码。

## 实测证据

2026-09-05，现有 20 组虚构样例加 3 组边界样例，在 PowerShell 7、Windows PowerShell 5.1 中分别与无头 Windows Edge 149 的浏览器解析器对照：每轮 **23 组，22 组一致，1 组已解释差异**。

- 字段重排：原 0 Token 修复为 100，与独立预设值及浏览器一致。
- 新增边界：事件类型位于 8,192 字符填充之后、回合 ID 位于长前缀之后、载荷中更深层的 `type` 干扰，全部一致。
- 原有回合识别、全部 Token 分量、首快照基线、重复与回退累计、多分段续接及拒绝条件回归一致。
- 唯一保留差异：截断 Token 样例，PowerShell 仍报告解析警告并保留部分结果，浏览器仍拒绝。此差异不算完整兼容通过。

测试副本只把四处用户目录表达式重定向到自行生成的虚构目录，并明确指定隔离报告路径；反向替换核对源码一致。没有执行原脚本默认会话发现入口，没有读取真实会话。测试副本和启动脚本使用 BOM；最终源码与已测算法文本相同。

仓库持续回归命令：`pwsh -NoProfile -File .github/scripts/Test-SessionRecordShape.ps1`。Windows PowerShell 5.1 可将命令开头换为 `powershell.exe`。该测试只加载源码中的纯解析函数，使用现有虚构 corpus 和补充长记录，不运行会话发现；两种运行时均已通过。完整仓库质量检查也调用该测试。完整 23 组跨解析器对照为本轮隔离实测，不等同于这条较小的持续回归测试。

## 截断记录：最小方案，尚未实施

一次静态读取无法证明文件仍在写入。建议仅增加完整性状态和显式重读核验，不自动跳过错误、不填零、不降低完整结果标准。

| 观察证据 | 建议状态与动作 |
|---|---|
| 最后一个非空记录解析失败，且文件末尾没有换行 | 标为“末尾不完整，可能仍在写入”；仅保留带缺口标记的已确认统计，不出完整评估结论 |
| 操作者主动重读后，原字节前缀保持一致且末条记录补全有效 | 可确认上次观察到的是未完成写入；重新分析新快照，不能只修补缓存中的数字 |
| 解析失败的记录后面还有其他记录 | 标为“历史记录损坏或格式不支持”；阻止该任务形成完整结论，并指出分段及行号 |
| 末尾有换行但解析失败，或重读后仍然不完整 | 标为“持续不完整，原因待确认”；文件未变化不能证明损坏，文件大小或修改时间变化也不能证明问题解决 |
| 文件变短、被替换或原字节前缀变化 | 原快照与缓存失效，从新输入重算；不得把新内容接到旧累计基线上 |

快照身份至少绑定内容指纹与解析器版本；大小、修改时间仅作提示。浏览器只能看到操作者选择的文件快照，重读需要再次主动选择，不能声称在监控原文件。实现时要通过合成的“两次读取”样例验证补全、稳定截断、中间损坏、重写和合法末行无换行；没有换行本身不代表错误。

缺失部分的 Token 必须标为未知，不能显示为已确认的零；受影响任务不能标为完整成功，其他独立任务不受阻断。本轮未实现这些新状态，也未改变原报告对截断输入的行为。

## 剩余边界

完整解析每条 JSON 可能增加大记录的计算与内存成本，尚无本修复的大文件性能结论；旧简化格式的 64 MiB 测试不适用。macOS/Safari、真实数据、全部报告指标和其他历史格式仍未验证。没有安装依赖、远端写入或启用真实数据读取。
