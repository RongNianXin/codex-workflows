# 截断状态方案：虚构快照验证

后续已完成[独立浏览器实验页与交互验证](TRUNCATION_BROWSER_RESULTS.md)。本文保留独立模型阶段的范围与证据，正式统计策略仍未改变。

## 结论与范围

独立实验模型的 28 项断言全部通过，支持继续验证完整性状态设计，不代表已修改或验证正式统计策略。本轮只新增实验脚本、报告及原提案入口。PowerShell 分析器和浏览器分析页均未修改；没有读取真实会话、安装依赖或执行远端写入。

模型使用自行构造的 UTF-8 JSONL 字节数组和两次读取快照，不扫描目录、不导入正式分析器、不计算 Token，也不模拟写入进程。它只识别一个明确的虚构 Token 记录结构；正式历史格式不在本轮验收范围内。

## 已验证的边界

| 分组 | 样例与确认结果 |
|---|---|
| 正常及空输入 | 合法末行无换行、LF、CRLF 可进入后续分析；空文件、纯空白不能标为成功 |
| 截断与损坏 | 末尾截断保留待确认；已换行的无效记录单独标记；中间损坏指出行号，后续空白行不算有效历史记录 |
| 格式检查 | JSON 可以解析但结构不支持、null、数组均不能进入后续分析；无换行的语法错误也不能自动认定为仍在写入 |
| 两次读取 | 原前缀不变且记录补全，确认快照补全；文件稳定不变或增长后仍不完整，继续待确认；补全后还有其他损坏时不算成功 |
| 缓存 | 内容改写、缩短、解析器版本变化、任务或分段变化均失效；大小和修改时间相同不能掩盖改写；仅修改时间改变而内容相同可复用原快照判定 |
| 编码 | 中文 UTF-8 字符只写入部分字节时不以替代字符强行解析；后续补全可以恢复；历史无效字节阻止完整结果 |
| 统计边界 | 只记录可识别记录数，不计算 Token；缺失 Token 标记为 null（未知），不填零；格式通过也不等于评估完成 |
| 分段与任务 | 新分段正常不能消除旧分段缺口；一个任务不完整不阻断另一个独立任务 |

## 对原方案的修正

1. “仍在写入”是可能原因，不是单次快照能确认的事实。即使第二次读取补全，也只能证明两次内容的关系，不能证明进程当时活跃。模型始终返回写入活跃状态未知。
2. 缓存复用与结果可用必须分开。相同截断内容可以复用“不完整”判定，但不能因此获得可用统计或完整结论。
3. 记录有效只是进入分析的前提。正式接入仍要核对会话元数据、回合、分段顺序、累计基线和完整格式；本模型不替代这些检查。
4. 字节完全相同的物理文件替换无法仅凭内容指纹识别。对当前内容分析可复用；若今后依赖文件身份或来源证明，需另设身份规则，不能声称已识别所有替换。

## 复现与证据

从仓库根目录运行：

```sh
node .github/scripts/Test-TruncationProposal.cjs
```

脚本仅依赖 Node 内置模块。预期输出 `count: 28`，每项 `result: PASS`；断言失败会以非零状态退出。若复现失败，应保留首个错误及 Node 版本，不能修改预期结果绕过失败。没有 Node 的机器无需为本轮安装，可直接查看源码中的输入和断言。

[实验脚本](../../.github/scripts/Test-TruncationProposal.cjs)包含全部虚构输入和逐项预期值，没有远端请求或文件读取。此次使用 Windows 上已有 Node 运行，退出码为 0。此次没有进行浏览器文件选择、操作系统写入竞态、macOS/Safari、大文件性能或正式分析器集成测试；28 项是模型断言通过，不是跨平台认证。
