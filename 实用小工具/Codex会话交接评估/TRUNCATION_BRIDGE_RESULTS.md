[打开独立衔接实验页](truncation-compatibility-lab.html)。本页使用带 `session_meta` 虚构标记的 JSONL，支持一次选择多个分段；没有改动 PowerShell 分析器、原兼容页或上阶段截断页。

## 结论

现有 20 组虚构样例回归通过：完整输入保持原浏览器解析结果，截断输入在调用统计前阻断，元数据冲突及分段重叠仍由原解析器拒绝。另加边界与页面操作检查，Windows Edge 149 共 32 项检查通过，HTTP 请求和页面异常均为 0。

这证明受测输入的衔接行为成立，不代表正式评估完整兼容。本轮没有读取真实会话、安装依赖或远端写入，也没有重新执行 PowerShell 对照；PowerShell 结果仍以此前的虚构回归为历史证据。

## 输入边界与实现

前阶段截断页使用专用实验头及单一 Token 结构，不能直接把它的输入交给兼容解析器。本轮另建独立页面，改用现有虚构 corpus 的会话字段结构。

数据流为：主动选择完整分段集合 → 数量与大小检查 → 按字节检查 UTF-8、JSON、对象外形和虚构元数据 → 全部分段通过 → 原兼容解析器 → 当前集合统计。完整性门禁只做进入解析器的前置检查，不替代完整格式校验、回合算法或分段规则。

兼容解析函数逐字复制，持续回归核对它与原页面的源码一致，未修改 Token、回合或分段算法。分段任一不完整则整组选中输入阻断，即便该段的内部 ID 属于其他虚构任务；这是一条保守的实验门禁，不改变原解析器对完整但 ID 不符分段的排除行为。重复文件名拒绝，以免同名分段排序产生歧义。

每次选择替换整组输入，从头计算，不合并旧快照、不沿用旧累计值、不缓存或监控文件。开始新读取时立即移除旧统计；失败也不把旧结果留作当前结果。页面只知道当前选中的集合，无法证明操作者选齐了任务的全部历史分段。

## 使用与剩余风险

打开 HTML，先下载并选择“截断分段”，预期显示未调用统计解析器；再下载并同时选择“完整分段 A、B”，预期得到 130 Token 和 1 次基线提醒。基线提醒表示后段的首个累计快照只作为比较起点，避免重复计算历史用量。若结果不符，提供页面状态与浏览器版本即可，不需要真实日志。

只接受虚构标记，单段限制 2 MiB、总计 16 MiB、最多 32 段；这些是实验限制，不是性能测试结论。标记不证明脱敏，勿选择真实资料。尚未验证 macOS/Safari、大文件性能、全部历史格式、正式报告或多任务目录发现。

## 后续补测：集合变更、读取异常与并发覆盖

现有无头 Windows Edge 149.0.4022.62 的 22 项专项检查全部通过。此次只增加测试与本节记录，衔接页、原兼容页及 PowerShell 分析器均未修改。当前未发现有证据支持的旧统计残留或旧结果覆盖问题。

| 检查 | 实测结果 |
|---|---|
| 集合增删 | 单段 A 为 100 Token，增加 B 后为 130，移除 B 后回到 100；旧段贡献不会残留 |
| 逆序与重复选择 | 逆序结果相同；重复选择确实重新调用解析器，结果不累加 |
| 无效集合 | 增加截断分段后清除旧统计且不调用解析器；移除截断分段可恢复；重复文件名拒绝 |
| 空选择 | 保留原快照；此项模拟取消后的无文件状态，不代表人工验证了系统文件对话框 |
| 读取异常 | 首文件失败不调用解析器；后续文件失败不输出已读部分的聚合；恢复后可正常统计；超限输入清除旧统计 |
| 读取期间 | 立即清除旧统计并禁用文件选择；清空仍可用 |
| 清空后旧读取返回 | 旧成功和旧失败均不改变清空状态 |
| 新结果已完成后旧读取返回 | 旧成功、旧失败均不能覆盖新结果及提示 |
| 新读取仍在等待时旧读取返回 | 旧读取的结束处理不能提前启用选择控件；新读取完成后正常展示并解锁 |
| 测试收口 | 所有受控读取均已结束；页面异常和 HTTP 请求均为 0 |
