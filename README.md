## 快速开始

### 使用 ChatGPT 网页脚本

1. 打开 [ChatGPT-Web](ChatGPT-Web/README.md)，根据说明安装篡改猴（Tampermonkey）。
2. 按浏览器要求开启“允许运行用户脚本”。
3. 选择需要的脚本安装，刷新 ChatGPT 网页后验证效果。

### 使用 Codex 总指挥工作流

1. 点击 GitHub 页面右上方的 `Code → Download ZIP`，下载并解压本仓库。
2. 打开 [01-操作者操作手册.md](总指挥工作流/第二代总指挥的工作模式/01-操作者操作手册.md)；日常使用主要看这一份。
3. 在真正要处理的项目中新建 Codex 任务，把下面这段话中的路径换成你解压后的规则目录，然后发送：

   ```text
   请把 <第二代总指挥规则目录> 作为本项目的总指挥工作流规则目录。先阅读 01-操作者操作手册.md，再根据我的目标按需读取其他规则并开始工作。
   ```

> [!IMPORTANT]
> 请在真正要处理的项目中打开 Codex，再登记这套规则目录。只有维护工作流本身时，才把本仓库作为目标项目。

## ChatGPT 与 Codex 的命名边界

仓库使用 **ChatGPT Workflows** 作为对外总标题，方便读者从 ChatGPT 的使用场景进入；**Codex** 仍用于准确指代编程、本地项目协作、CLI、会话格式以及只适用于 Codex 的工作流和工具。

因此，不会为了统一品牌而批量改写目录名、脚本名、命令或技术文档中的 `Codex`。标题中的 ChatGPT 也不表示每个模块都能在普通网页聊天中运行；具体适用对象、前置条件和限制仍以各模块 README 为准。

## README 双语约定

公开子目录只要提供 `README.md`，就同时提供 `README.en.md`，并在顶部互相链接。中文页是内容源；英文页保存中文源内容的 SHA-256 同步标记。仓库质量脚本会递归检查文件是否成对、切换链接是否存在、中文更新后英文页是否已经重新确认。

这个门禁能防止漏建英文页和旧译文悄悄滞后，但不能自动证明翻译语义正确。每次提交前仍须对照检查目标、步骤、命令、权限、安全边界和限制；存在歧义时保留原术语并标为待确认。

## 总指挥工作流怎么读

日常使用只需要先看 [01-操作者操作手册.md](总指挥工作流/第二代总指挥的工作模式/01-操作者操作手册.md)：

1. 按手册登记本地规则目录。
2. 根据目标选择场景，复制提示词并填写必要信息。
3. 其余 `00`、`02`～`11` 交给 AI 按规则注册表核对和读取。

[00-第二代工作流总览.md](总指挥工作流/第二代总指挥的工作模式/00-第二代工作流总览.md) 是架构地图和规则注册表；需要理解整体设计、阅读顺序或排查规则冲突时再查看。正常交接可使用 [总指挥轻量交接启动配置.md](总指挥工作流/第二代总指挥的工作模式/总指挥轻量交接启动配置.md)。

“第二代”是当前公开规则系列的版本名称，不要求读者先了解某套“第一代”。新用户直接使用当前规则；[08-旧版兼容与迁移规范.md](总指挥工作流/第二代总指挥的工作模式/08-旧版兼容与迁移规范.md) 仅供已经运行其他旧版或自建总指挥流程的项目迁移时使用，日常无需读取。

## 可选的本地操作者协作画像

协作画像让 AI 记住经过验证的技术偏好、理解程度、有效协作方式和常见操作疏忽，从而少做重复解释，并在容易出错的步骤提前提醒。它不是身份档案，也不能替代项目事实、测试或授权。

它默认关闭。第一次建立总指挥时，AI 会在完成主回复后介绍一次；只有明确同意才会启用，拒绝或不回答都不会收集，也不会在同一项目后续交接中反复询问。启用后，只在重大 Goal/里程碑形成稳定截点、总指挥准备交接、同类协作问题再次出现，或你主动要求时做一次本地检查；没有合格新证据就不写，过期、重复和被新证据推翻的内容优先清理，不使用定时任务或后台监控。

可直接用自然语言控制：

- 开启：`开启本地操作者协作画像`
- 暂停或恢复：`暂停本地操作者协作画像` / `继续本地操作者协作画像`
- 关闭：`关闭本地操作者协作画像`
- 关闭并删除本地数据：`关闭并删除本地操作者协作画像`
- 只看安全状态：`查看本地操作者协作画像状态`

隐私边界有可核对的证据：真实画像只放在 `.gitignore` 精确排除的本地文件中，启用和每次写入前后都会核验忽略规则实际命中且文件未被 Git 跟踪；不记录身份、联系方式、真实项目、本地路径、聊天原文、敏感属性或人格评价；索引和交接只传状态与通用指针，不传正文或内容哈希；最多保留 20 条活动记录并设置过期复核；任何派生公开副本都要先展示最终脱敏载荷，再由操作者在下一条独立消息第二次精确确认。`.gitignore` 不是加密或操作系统权限，因此高度敏感资料仍不应放入画像。完整规则见 [11-操作者协作画像规范.md](总指挥工作流/第二代总指挥的工作模式/11-操作者协作画像规范.md)。删除公开的 11 号规范不是关闭开关，也不会删除本地数据。

## 隐私与公开边界

- `.gitignore` 负责阻止 Git 跟踪本地私人文件；它不是访问权限系统。
- `AGENTS.md` 进一步要求 AI 未经明确授权不得读取、修改或上传私人目录和自用文件。
- 仓库所有者明确授权的公开署名或品牌素材可以用于 README 等公开展示；该授权不覆盖本地路径、任务记录、凭据或第三方个人信息。
- 高度敏感资料仍建议放在仓库和 Codex 工作区之外。
- 提交前应核对 `git status`、`git diff --cached`，并执行敏感信息扫描。
