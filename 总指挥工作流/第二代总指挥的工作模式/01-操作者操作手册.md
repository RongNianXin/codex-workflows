# 第二代工作流操作者操作手册

本手册告诉你什么时候使用、填写什么、复制哪段，以及成功后应看到什么。AI 的执行细则由其他规则文档维护，你不需要逐份阅读或手工填写技术参数。首次使用先登记完整规则目录；不要只提供某一段提示词而遗漏配套规则。

## 怎样阅读和复制

每个场景统一分为两部分：

- **操作说明（不要复制）**：告诉你什么时候使用、哪些字段需要填写，以及成功后应该看到什么。
- **复制提示词（整段复制）**：标题下面的代码块才是要发给 AI 的内容。标注“替换 `【】`”时先填写占位内容；标注“直接整段复制”时不需要修改。然后从代码框第一行复制到最后一行。

`【必填】` 表示执行相关动作前必须确定的信息；使用下方统一入口时，能从已授权访问的事实源核实的字段由 AI 补齐，无法核实的再向你询问，不要求你重复抄写。`【可选】` 已给出默认值，没有特殊情况就保留“无”或“由 AI 判断”。代码框外的解释文字不用发给 AI。

### 需要给其他窗口发提示词时

直接告诉当前 AI 你要交接、恢复还是委派任务。它会使用适用模板，补齐能核实的信息，并告诉你发给哪个窗口；不知道的必要信息再问你。你选择自己发送时，复制完整提示词即可，准备提示词不会自动建窗口、发送消息或切换总指挥。

如果希望另一个窗口直接做事，请明确说“请让该窗口执行这项工作”，并说明目标与限制。AI 会传递你已有的授权；接收方核实后无需重复问同一个授权问题。通知、提建议与执行是不同要求；新增动作或必须由你亲自确认的事项仍会单独询问。接收方正在处理其他任务时可能排队，收到消息不等于已经完成。

## 先记住 4 条

1. 你只需要说清楚目标、偏好，以及 AI 无法从项目中读取的人工决定或线下信息。
2. AI 负责读取项目、GitHub、规则和状态记录，自动判断范围、分支、冲突、测试、责任和下一步。
3. 本地修改、测试和 Commit 可以在已确认范围内连续执行；Push、PR、Comment、Review、Approve、Merge、部署等远端写入，必须在执行前得到你的明确确认。
4. 不确定用哪个场景时直接描述目标。AI 应自动选择或纠正场景；只有不同选择会明显改变范围、风险或结果时，才向你提最少的问题。

你可以直接说目标、描述现象，或说“不知道哪里有问题”，不必先学技术术语或重复审查要求。AI 会核对事实、风险和验证结果；需要你决定时，说明原因并给出最少步骤。你回答“不确定”时，AI 会继续核对，不能把它当作通过。

## 统一入口：描述目标，由 AI 核对场景

> **操作说明｜不要复制**

知道想得到什么结果，但不想逐项填模板时使用。填写目标即可，场景可以留空。先提供完整规则包，或按下方步骤登记规则目录；AI 会核对适用场景，只向你询问无法自行确认的必要信息。选择场景不会自动改变当前窗口的身份或扩大权限。也可以直接用日常语言说明目的，不必照抄模板、记编号或使用固定说法；AI 先区分你要执行、了解、反馈还是暂停，再结合现状选择下面已有入口。确认命中正式场景时，第一次实质回复会先显示“场景判断：场景编号（名称）；依据：简要理由”；这只是路由说明，不代表已经取得授权或完成任务。

> **复制提示词｜填写目标；场景可留空**

```text
我的目标是：【描述希望得到的结果】。
我初步判断适用：【场景名称或编号；不确定可留空】。

请依据随附工作流或已登记且有权访问的规则目录，先核对场景是否适配，再按适用场景执行。我的场景判断仅供参考；若不适配，请简述原因并选择更合适的场景。选择会明显改变范围、风险或交付时，先向我澄清。

能从已授权访问的项目和状态中核实的参数，请自行补齐；不得猜测。缺少会影响范围、结果或权限的信息时，集中向我提出最少的问题，其他安全且不依赖这些答案的工作继续。规则或事实源无法读取时，明确说明缺口。

开始前简短说明所选场景、预期交付和关键待确认项；简单任务不必展开计划。保持原流程的验证标准、角色边界、停止条件和授权要求，不因本入口取得总指挥调度权。模板中的授权示例不代表我的实际授权，不继承旧任务授权。
```

**预期结果：**AI 说明采用哪个场景和交付什么，自行核实可读取的参数，只追问必要缺口，再按原场景执行和验证。你不必重新填写整段专业提示词；这不会降低验证标准，也不保证 AI 每次都能正确选场景。若理解偏离，只需指出“目标或场景理解有误”并补充差异，AI 应重新核对受影响的计划与动作。

## 完全不确定时直接这样说

> **操作说明｜不要复制**

你不需要回忆全部改动，也不要为了填表猜答案。下面这段会让 AI 先保护工作区、恢复客观事实和完成能自动执行的验证；仍需要你观察时，AI 只提供已经准备好的页面、输入和少量选项。`不确定`是合法反馈，但不等于通过。

> **复制提示词｜直接整段复制**

```text
我不确定当前具体修改了哪些内容，也没有可靠的人工验收记录。

请先不要执行远端写入。自动保护当前工作区，从任务记录、Git Diff、未提交、未跟踪、与当前任务有关的忽略文件、依赖、配置、模型、资产和已有验证中恢复修改范围，区分正式候选、无关修改、临时内容和待确认项；不要为了恢复而清理、覆盖或提交来源不明修改。

优先完成能够客观执行的验证。需要人工观察时，把正确页面、输入和最少步骤准备好，只让我选择“符合预期 / 不符合预期 / 不确定”。请同时给出可直接复制的示例回答，不要让我填写技术字段。证据仍不足时保留本地候选或 Draft，不要宣称已经通过，也不要执行 Push、PR、Comment、Review、Merge 或其他远端写入。
```

## 最常用的入口

每次汇报会告诉你现在是否需要操作。需要时，AI 提供最少步骤或可直接发送的确认语；不需要时，说明下一步由谁处理。

| 你要做什么 | 使用 |
| --- | --- |
| 知道目标，不想逐项填写提示词 | 上面的“统一入口：描述目标，由 AI 核对场景” |
| 不记得本地改动或没有验收记录 | 上面的“完全不确定时直接这样说” |
| 第一次启动或恢复当前项目的总指挥 | 场景 1 |
| 提出一个普通开发或文档目标 | 场景 2 |
| 将会议、问题或规划转成工作项并推进 | 场景 2A |
| 先在本地反复开发和验收，再准备发布 | 场景 2B |
| 保持现有功能不变，清理重复或多余代码 | 场景 2G（旧编号 2B-1） |
| 输出不符合预期，不知道问题在哪一层 | 场景 2C |
| 本地与远端长期未同步，双方都产生了更新 | 场景 2D |
| 把本轮成果运行起来，实际检查效果 | 场景 2E |
| 让两个不同 AI 窗口分别执行和独立审查；或恢复这组协作 | 场景 2F |
| 全量接管协作队列中的 Issue/PR | 场景 3A |
| 在可靠截点上继续增量推进 | 场景 3B |
| 审查并收口明显过时的 Issue/PR | 场景 3C |
| 查看当前进展或最新拓扑 | 场景 4 |
| 汇总我需要操作的事项，或反馈检查结果 | 场景 4A；已有任务反馈仍回到原工作项 |
| 让原任务继续，在另一任务中只读解释某个对象 | 场景 4B；只有明确要求时才创建新任务 |
| 项目目标、条件或工具发生变化 | 场景 5 |
| 准备交接给下一任总指挥 | 场景 6 |
| 新总指挥接收正常交接 | 场景 6A |
| 任意任务窗口中断后，在新窗口恢复并继续 | 场景 6B |
| 当前聊天偏离主线，想把未完成主线移到新聊天 | “换新聊天或归档前：先准备续接材料” |
| 准备归档仍有未完成工作的当前对话 | “换新聊天或归档前：先准备续接材料”；总指挥换任仍用场景 6 |
| 复盘最近一批工作的执行方式 | 场景 7 |
| 暂停当前工作，保留恢复条件 | 场景 8 |
| 任务较长且出现额度不足风险 | 可选功能：长任务额度保护 |
| 让 AI 记住稳定的技术协作习惯 | 可选功能：本地操作者协作画像 |
| 第一次提供规则，或规则目录已移动 | “登记规则目录” |
| 卡顿时降低资源占用，或从可靠断点继续 | “两条快捷指令” |
| 发布或推送当前成果 | 既有发布准备流程及“远端写入怎样确认”；AI 按需加载 PR 标准 |

这张表用于按目的定位，不是关键词匹配表。精简代码选 2G，改变算法效果另列目标；本地继续开发选 2B，双方都有改动且要汇合才选 2D；需要两个不同 AI 窗口形成“执行＋独立审查”配对时选 2F，已有窗口和配对优先复用；普通 PR 审查按 PR 标准处理。交接要区分旧窗口准备（6）、候选接收（6A）和中断恢复（6B），不能只凭“继续”或“接管”改变角色。只想了解某个场景时，AI 只解释，不启动它；只要求当前窗口自己检查工作，也不自动创建 2F 配对。

全量推进适合首次接管、长期未处理、范围或协作者变化、怀疑遗漏、历史截点不可靠。增量推进适合已有可靠截点，只处理新增或变化对象、未闭环旧账、派生对象和最小依赖。不确定时用场景 3B；AI 发现截点不可靠时应自动升级为全量，不要求你查历史编号。

## 首次使用 3 步

1. 把本工作流下载或克隆到一个稳定的本地目录。
2. 在 Codex Desktop 中打开真正要开发或管理的目标项目；不要打开本规则仓库，除非你正在维护规则本身。
3. 执行下面的“登记规则目录”，然后使用场景 1 建立总指挥。

本工作流当前直接适用于 GitHub；其他托管平台需要先适配平台能力和授权规则。

## 首次使用或规则目录移动后：登记规则目录

> **操作说明｜不要复制**

平时不需要重复登记。只有首次使用、换电脑或移动了规则文件夹时，填写规则文件夹绝对路径。

> **复制提示词｜替换【】后整段复制**

```text
第二代总指挥规则保存在【规则文件夹绝对路径】。请验证规则入口和文件完整性，并登记为当前项目的规则目录。本次只登记规则，不修改产品，不执行远端写入。
```

成功时，AI 应说明“验证通过并已登记”；失败时只告诉你缺少什么或路径哪里不对，不要求你逐个上传规则文件。

## 场景 1：首次启动或恢复总指挥

> **操作说明｜不要复制**

在全新的总指挥任务中使用。必填远端仓库 URL 和本人 GitHub 登录账号；规则目录已经登记时保留“自动定位”，否则填写规则文件夹路径。

> **复制提示词｜替换【】后整段复制**

```text
远端仓库地址：【必填：完整 GitHub 仓库 URL】
使用者本人 GitHub 登录账号：【必填：GitHub 用户名，不是显示昵称】
第二代规则目录：【自动定位 / 规则文件夹绝对路径】

请在当前项目建立或恢复唯一总指挥。先核对当前本地项目的 Git remote 与上面的远端仓库、当前实际登录账号与填写账号是否一致，再读取项目规则、状态记录、代码、Git 和 GitHub 当前事实。只读确认项目范围、当前目标、已完成事项、活跃工作、工作区状态、远端状态、阻断和下一步。

判断这是首次启动、正常恢复、目标变化还是控制面冲突。本轮先不要修改产品、不要创建重复状态记录，也不要执行远端写入。规则入口无法定位时，只向我索要一次规则文件夹路径。仓库不一致时只暂停受影响的仓库动作并说明差异，不要猜测或修改 remote。
```

**预期结果：**AI 说明当前目标、事实基线、活跃工作、阻断和下一波次；不会立即修改代码或 GitHub。如果本项目从未介绍过本地协作画像，AI 会在主回复后用不超过 150 字介绍一次；拒绝或不回答都不会启用，也不会在同一项目后续交接中反复询问。

## 场景 2：提出普通目标

> **操作说明｜不要复制**

必填仓库 URL 和目标。只有确实存在额外限制时才修改“补充限制”。

> **复制提示词｜替换【】后整段复制**

```text
远端仓库地址：【必填：完整 GitHub 仓库 URL / 仅本地项目】
第二代规则目录：【自动定位 / 规则文件夹绝对路径】
目标：【必填：用自然语言描述本轮目标】
补充限制或业务验收：【可选：无 / 具体限制或验收要求】

请自动读取相关规则、状态、代码和仓库事实，核对本地项目与指定仓库，明确范围、验收标准、排除项、基线、依赖和停止条件。先做必要的只读检查和对抗式审查；只有不同解释会明显改变范围、风险、成本或对外行为时，才向我提最少的问题。

先生成一张简明执行卡，说明推荐方案、最坏后果、硬禁止项、自动执行范围、验证和紧急停止条件；技术值放附录。我集中确认后，由总指挥连续完成所有已授权且不受阻的本地工作。只有确有全流程净收益或必须独立审查/隔离时才创建最少量专项任务。远端写入另行生成最小确认文本。
```

## 场景 2A：把会议、问题或规划转成工作项并推进

> **操作说明｜不要复制**

把会议记录、问题描述或附件直接发给 AI。必填仓库 URL、本人 GitHub 登录账号和目标；没有协作者就填“无”。其他字段已给默认值。

> **复制提示词｜替换【】后整段复制**

```text
远端仓库地址：【必填：完整 GitHub 仓库 URL】
使用者本人 GitHub 登录账号：【必填：GitHub 用户名，不是显示昵称】
第二代规则目录：【自动定位 / 规则文件夹绝对路径】
目标模块或母任务：【必填：一个或多个目标】
本轮协作成员 GitHub 登录账号：【必填：一个或多个账号 / 无】
推进模式：【可选：端到端推进 / 仅创建 Issue；默认端到端推进】
附件或原始记录：【可选：已附附件 / 本地路径 / 无】
责任安排、业务限制或线下决定：【可选：由 AI 根据现有证据建议 / 自然语言补充】

请把我提供的会议结论、问题描述或规划转为可执行 GitHub 工作项。先核对本地仓库与远端 URL，读取 Issue 模板、标签、贡献规则、分支保护、Review 和合并门禁；扫描现有 Issue/PR 去重并建立必要依赖，材料按必要、辅助、重复、冲突和待确认分类。

第一阶段只读生成一张合并执行卡，覆盖拟创建或更新的 Issue、责任与候选负责人、实现单元、分支、真实交付 PR、Issue 关联、Reviewer、验证、失败回退、禁止项和交棒终点。候选负责人不得自动设为 Assignee；不得创建没有真实交付的空 PR。

我集中确认后，在同一母任务内按卡推进到仓库规则允许的最远位置。缺少某个非当前阶段条件时只暂停受影响动作。Approve、Merge、Close、部署和其他未列远端动作仍须单独授权。结束时输出 Issue 依赖、PR 堆叠关系、当前行动方、外部门禁和我的必要人工操作。
```

**预期结果：**AI 先给出查重、依赖、责任与执行卡；确认后才创建或修改远端对象。

## 场景 2B：本地连续开发，验收后准备发布

> **操作说明｜不要复制**

一个功能需要反复修改、测试和你亲自观察，暂时不准备逐轮更新远端时使用。填写具体目标，发给承担该项目开发协调的当前总指挥；它应明确接收窗口和实际执行者，不因这份模板更换已有分工。已有项目的仓库地址、本人账号等信息由 AI 从本轮有效事实源恢复并核验，无法确认且影响当前动作时再集中询问，不让你重复填写已知信息。

例如：文件导入功能需要先处理格式错误，再调整反馈提示；你在本地检查，不满意就继续修改，验收满足后才准备 PR。这里的“准备发布”不等于已授权发布，也不要求把所有改动合成一个大 Commit 或 PR。

只想精简现有代码时，直接使用[场景 2G](#场景-2g保持功能不变精简现有代码)，无需再发送 2B 模板。需要建立或调整执行—审查配对时使用 2F；已有适用配对按当前契约复用，不重复建任务。

> **复制提示词｜替换【】后整段复制**

```text
远端仓库地址：【自动恢复并核验 / 完整 GitHub 仓库 URL】
```

**预期结果：**AI 先报告双边基线、分叉关系、重叠范围、风险与推荐方案；经确认才改变本地状态，完成后以新 Head 重新验证并生成另一张远端执行卡。任一阶段事实变化时，只暂停并重算受影响部分。

## 场景 2E：把本轮成果运行起来，交给我检查

> **操作说明｜不要复制**

一轮修改准备好，你想打开程序或页面检查效果时使用。AI 会先核对应该运行哪个版本，避免你检查到旧程序。这可以是在本机启动，不代表项目全部完成，也不默认发布到公网。

填写这次要检查的功能，例如“图片预览功能”。如果要用手机等其他设备检查，补充设备和访问范围；分支、模型、端口等技术参数由 AI 核实。

> **复制提示词｜填写【具体目标】后整段复制**

```text
请把【具体目标】(示例：图片预览功能) 这一轮准备让我验收的成果运行起来，给我可打开的入口，并确认实际运行的是本轮要检查的代码和配置。

能自行核实的技术参数由你补齐。如果有多个版本，请结合本轮目标和已有验证结果推荐，不要只选版本号最大或已经运行的那个；无法确定时再问我，并保留现有改动。

请按已登记规则中的“低信息部署请求与运行身份交付门禁”核对，规则无法读取时说明缺口，不得声称已经完成核验。只在我已明确授权的范围内操作；涉及公开或共享发布、费用、高资源验证、停止现有服务等尚未授权的动作时，先完成不受影响的核对，再说明需要我确认什么。

完成后，请实际打开或请求交付入口，确认运行版本；需要多个设备访问时，核对它们是否指向同一版本。告诉我应该检查什么，分别说明入口是否可用、是否运行了正确版本；效果是否通过，由我实际查看后确认。
```

**预期结果：**你得到打开方式、版本核对结果和简短检查步骤。页面能打开，不等于运行版本正确；运行版本正确，也不等于效果已经通过你的验收。无法证明版本正确时，AI 会说明缺口，不把旧入口当作本轮成果交付。

**遇到问题：**打不开或效果不符合预期时，提供错误提示或脱敏截图，并说明在哪一步出现；不要发送账号凭据或未经脱敏的日志。你暂时无法判断时，可以直接说“不确定，请继续核对”。

## 场景 2F：跨窗口执行与独立审查协作

适用于让两个不同 AI 窗口分别承担“执行”和“独立审查”。这两个是本工作项里的逻辑角色：可以由总指挥、普通任务或专项任务承担，不要求固定创建两个专项任务。当前窗口适合执行时，只补一个独立审查窗口；当前总指挥只负责协调时，才按需要安排执行和审查两个窗口。已有适用窗口优先复用。

**建立、切换或不知道找谁时，发给当前负责安排的 AI；项目已有总指挥时优先发给总指挥。**建立好后，普通要求、截图和不满意反馈直接发执行窗口。执行者交原独立审查者，按约定有限互审；结束或遇到例外时交收口窗口，项目有总指挥时由总指挥最终汇总。无需每次说“场景 2F”，也不用向所有窗口重复发送相同内容。若两个总指挥参与，只能有一个保留项目中央调度权和单写权，另一个只承担本工作项的执行或独立审查角色。

下列代码框可直接复制；仅 2F-1、2F-2、2F-5 中替换工作项名称，2F-1 补充目标。2F-3、2F-4 把真实反馈或附件随消息发送，不必自己填版本、轮次或 ID。窗口身份、配对、路由和技术参数由 AI 核实；无法识别工作项时只问一个定位问题。详细角色职责、转交和返工规则见 [协作规范](docs/EXECUTION_AND_INDEPENDENT_REVIEW.md)。

### 2F-1：建立执行与审查配对｜发给当前负责安排的 AI

```text
我要开展【工作项】，目标是【用途与预期结果】。请按场景 2F 建立“执行者＋独立审查者”配对。先核实当前窗口和已有任务适合承担哪个逻辑角色并优先复用；当前窗口可以执行时，只创建一个独立审查任务；仍缺角色时，授权创建满足配对所需的最少量独立任务。授权你在本工作项内联络配对窗口，并允许双方直接转交成果、意见和修订；结束或阻断时交负责收口的窗口。
请建立共同契约，并让双方确认：我的普通反馈直接发执行者；允许范围内的工作不需逐次中转。默认每批两轮、最多三轮；收口后我的新反馈可按契约触发有限返工，重复失败不清零绕过上限。存在项目总指挥时保持其中央调度与单写权唯一，其他总指挥只承担本工作项角色。

```

操作：只发给当前负责安排的 AI；项目有总指挥时优先发给总指挥。等待它说明实际使用的窗口、各自职责和收口方；如要实施，在它给出的具体任务包上确认。预期：双方知道彼此和汇报对象，按允许范围完成工作。异常：无法创建或联络时，由收口方给最小人工替代步骤；不自行建重复窗口或 Fork。示例“研发算法 B”只替换工作项与目标，不表示阅读手册就创建任务。

### 2F-2：已有窗口改用新流程｜发给当前负责安排的 AI

```text
请把【工作项】已有执行者和独立审查者迁移到最新跨窗口执行—独立审查约定，不重建任务、不改变它们原有身份。授权你通知双方读取、确认逻辑角色、配对和收口对象；授权该配对在本工作项内有界直联，并覆盖我后续明确反馈触发的有限返工通信。
```

操作：等待总指挥明确“两个窗口分别确认”，而不是只说文档已修改。预期：以后给执行者短反馈即可，它按持久约定继续交原审查者。异常：一方未确认或不可达时，等总指挥给具体回退；你不必反复粘贴角色提示词。

### 2F-3：本批补充反馈｜发给执行窗口

```text
这是当前工作项的补充反馈，请保留我的原始描述和附件，核对对应成果。在已有权限内处理并按当前约定交原审查者；不要新建重复任务或清零本批轮次。需要新增权限、无法访问附件或意思不明确时，说明具体缺口。最终由总指挥汇总。
```

操作：随消息附现象/要求/截图，或直接用自然语言说清这些信息。预期：执行者说明本次处理什么、由谁继续、你需做什么或等待什么，并在授权内推进；缺权限时给具体方案和确认项，不能只说已汇报。审查者能读必要原始证据。异常：没有接收说明时，向总指挥说明已发给哪个窗口，由总指挥核对投递和状态；不要重复发送多份任务。不给固定等待秒数，不创建后台轮询。

如果反馈已发给审查者，无需重发：它应按有效权限转交并说明下一步；尚不能转交时，给出具体联络缺口。总指挥收到后负责给出处理决定，不只登记。

### 2F-4：结果不满意，需要再改｜发给原执行窗口

```text
我对刚才的结果还有这些不满意之处，具体说明和证据随本消息提供。请按共同协作约定核对旧批次和当前权限：符合有限返工条件就建立关联返工批次，改完直接交原审查者复核，结束或阻断时回报总指挥。保留我的原始要求和前轮结论，不把同一失败反复清零；缺权限或需要改变方案时先说明。
```

操作：告诉执行者“哪里不满意、希望怎样”，有证据就附上。不必重贴整套规则；已有配对收到等价自然语言也必须走同一流程。预期：执行者说明“在本批继续/有限返工/具体阻断”，你等待总指挥最终汇总。若只收到执行者单独完成声明却没有交审查或回报，应把该声明交总指挥核账。

返工不是无限续跑。原批次尚未结束则沿用轮次；已收口且有新证据或明确新要求、范围权限不变，按契约开有限批次并通知总指挥。相同问题已到上限、连续近似修补无改善或没有新证据/可验证的新方案时先交总指挥判断。你无需自己决定轮次或技术权限，AI 自动核对；反馈本身不授予高资源运行或远端写入。

### 2F-5：换任恢复｜发给当前负责安排的 AI

```text
请恢复【工作项】现有执行者和独立审查者的协作关系，核对共同契约、当前成果、累计轮次、原身份、逻辑角色和当前收口方。授权你向双方通知当前汇报对象、配对、世代和边界，并授权它们回复确认。本次只恢复联络，不启动业务；不改变已有中央调度权，直联及返工权限按当前有效授权核对，缺少哪项就说明，不继承旧权限。请告诉我应该直接反馈给哪个执行窗口。
```

预期：相关角色分别明确确认；不重跑旧成果。异常：总指挥提供一条准确转交内容和目标窗口，必要时你人工转交并回传确认/错误，无需搬运完整聊天。

### 2F-6：目标或权限变化、找不到入口｜发给当前负责安排的 AI

```text
我想调整当前工作，具体想法随本消息说明。请先核对与已有任务、成果和权限的关系，能继续复用就复用；需要新目标或额外权限时给我具体方案。不要仅因我提出想法就创建新任务、运行高资源验证或写远端。
```

正常反馈可直达执行者，涉及取消、暂停、改目标或重要取舍优先找总指挥。总指挥只负责必要的范围判断和终点核账，不把正常互审重新变成每步转发。审查达标不代表操作者已满意；操作者反馈与专业验收仍分别记录。

## 场景 2G：保持功能不变，精简现有代码

> **操作说明｜不要复制**

想清理重复实现、旧代码或过于复杂的结构，但不想改变现有功能时使用。填写要整理的范围，例如“文件导入功能”；不知道哪些文件能删也没关系。AI 先查清入口和依赖、保存可比较的原有表现，再给出分批方案。发给承担该项目开发协调的当前总指挥，由它按项目分工安排实际执行者。此入口与 2B 平级，引用 2B 的本地确认、验收和发布门禁；只发送本节模板即可，不需要先执行 2B。需要建立或调整执行—审查协作时再用 2F；已有适用配对按当前契约复用，不因选中本场景自动建任务或取得通信权限。

旧编号 2B-1 现在统一指向本场景，含义和验证要求保持不变。收到旧提示词时，AI 应说明已映射到 2G，并按当前规则核验范围与权限，不能把旧模板当成新的实施授权。

精简要有实际收益，例如减少重复维护、状态转换或资源开销，同时守住效果和功能不退化。不是每次都能加速；没有足够收益时可以不改。若目标是提升算法准确率或改变效果，应另列目标，不混入这轮精简。

> **复制提示词｜填写【整理范围】后整段复制，发给当前总指挥**

```text
请检查【整理范围】中是否有能够安全精简的重复代码、旧实现或复杂结构，保持现有功能、接口和用户操作不变。

先按已登记工作流的“行为保持型代码精简”规则，只读查清实际入口、调用和数据流，区分确定可处理、需要保留和证据不足的部分。不要预设代码一定冗余，也不要只凭没有搜到调用就删除。

请自行补齐能核实的技术参数，准备修改前后的对照基线、分批修改与恢复方案、自动检查和最少人工验收步骤；说明由当前窗口执行、复用已有配对还是另建专项更合适。新建任务和通信按现有权限处理。

先把具体范围、拟删除或合并的内容、验证方法与风险给我确认，再修改。已有明确授权的同范围事项不重复询问。不要改算法效果、增加功能或顺手处理其他模块；不执行远端写入。

请在修改前明确本批收益目标与不能退化的条件。完成后告诉我删了什么、合并了什么、为什么保留其他部分、整体复杂度或代码量怎样变化，以及哪些结果已验证、哪些仍需人工确认。只减少行数或让总评分掩盖关键样本退化，不能算验收通过。
```

**预期结果：**先得到有依据的精简方案；确认后按小批次修改，每批都能恢复并与原版比较。人工核验时，AI 准备好正确入口、相同输入和简短步骤；发现效果或操作变化时说明具体现象，AI 应停止受影响批次并排查，不能临时放宽标准。

```text
正文只保留聚合结论和稳定指针，不复制完整聊天、Git 清单、日志、Diff 或旧截图。未通过稳定截点和结束覆盖核账前，不停止当前总指挥，也不启动新总指挥调度。完成后告诉我交接材料的位置、检查结果和是否达到可切换条件。
```

## 场景 6A：新总指挥接收正常交接

> **操作说明｜不要复制**

**第一步：在新任务中建立候选**

> **复制提示词｜替换【】后整段复制**

```text
你现在是本项目的新总指挥候选。请读取【必填：交接快照路径或已附附件】，并完整读取交接材料指定的轻量交接启动配置。核对配置及 02、04、07、09、10 的来源指纹；只有异常项才展开对应规则，影响范围无法判断时才全文回退。

只读核对：快照有效期、旧总指挥世代与单写者、当前目标和精确断点、工作区/分支/worktree/未提交修改、代码与 Git/GitHub 基线、验证证据、阻断、禁止项、恢复和失效条件。默认只返回聚合状态；仅对冲突最小展开。请告诉我恢复置信度、已确认事实、冲突或缺口、候选接管截点，以及是否达到可切换条件。确认切换前不得取得中央调度权。
```

只有新任务明确报告“达到可切换条件”后，你先停止或归档旧总指挥，再执行第二步。

**第二步：正式切换**

> **复制提示词｜直接整段复制**

```text
我已停止或归档旧总指挥，确认把本项目总指挥调度权切换给你。

请先最小复核：轻量启动配置和来源指纹、中央世代与单写者、候选截点失效条件、工作区聚合状态和当前远端基线。仍可靠时，把候选截点升级为正式接管截点，登记新的唯一总指挥，并把旧总指挥标记为已停止调度但保留历史。回读中央状态，确认单写者唯一、旧授权未继承，然后只从交接快照的精确断点继续。按 04“正式切换后的专项联络恢复”核对专项汇报对象；只在本轮有效通信授权内通知并核验确认，没有授权时报告受影响项，不自行联系或重建任务。未包含在我当前明确指令中的产品修改和远端写入仍未授权。
```

## 场景 6B：任务中断后恢复并继续

> **操作说明｜不要复制**

适用于任何普通、专项或总指挥任务因为额度耗尽、程序异常、账号切换等原因中断后，在新窗口恢复现场。它不会把普通任务或专项任务升级为总指挥。原窗口仍能继续时，直接说“从断点继续”；旧总指挥还能正常生成正式交接时，优先使用场景 6 和 6A。

先判断是否值得使用本场景：如果原任务很简单、完整指令可以直接重发、没有要保留的中间成果或未提交修改，也没有结果未知的外部动作，直接重发原任务通常更快，不必使用场景 6B。只要这些条件有一项不确定，或任务已有值得复用的产物、复杂要求变化、昂贵验证和潜在副作用，再使用下面的恢复提示词。

对话摘录、状态记录和项目路径都不是固定必填项。知道就填，不知道写“自动恢复”；只有当前任务实际涉及 Git、远端仓库、项目规则或中央状态时，AI 才核对这些内容。AI 会先比较恢复成本与安全重做成本：简单、确定、没有可复用成果或结果未知动作的任务可以直接重做；已有重要产物、复杂需求变更、昂贵验证或外部副作用时才深入恢复。完整对话摘录有助于恢复全部可见要求和公开决策过程，但 AI 不能恢复不可见的内部推理；真正的恢复目标是重新建立足够继续执行的任务契约、事实、产物、验证和精确断点。

> **复制提示词｜替换【】后整段复制**

```text
当前任务因【额度耗尽 / 程序异常 / 账号切换 / 其他原因】中断。请恢复这个窗口原本承担的任务，并从可靠断点继续完成；不得因为本提示词而改变身份、扩大职责或把普通/专项任务升级为总指挥。

可用恢复材料：【自动恢复 / 已附对话摘录 / 交接记录或状态文件 / 其他精确材料】
我记得的原任务目标：【自动恢复 / 简要说明】

先只读识别原窗口身份、任务范围和中断状态。身份只能依据当前指令、任务创建信息、适用规则、已有任务记录或其他可验证证据确定：普通任务保持普通任务；专项任务只恢复原任务卡、文件/工作区边界、向总指挥回传的关系和自身断点，不得读取或写入中央总指挥状态；只有证据明确表明原窗口本来就是总指挥，且我在当前消息中明确任命接管时，才进入总指挥的无正式交接恢复。

在展开长对话、完整日志、全仓历史或中央状态前，先执行恢复收益门禁，只用当前消息、任务身份、现有产物/工作区摘要和结果未知信号判断路线：`直接重做 / 快速恢复 / 深度恢复 / 必须先核账`。简单且可确定重现、当前消息已包含完整目标、没有值得复用的中间成果或未核验外部动作，并且目标工作区洁净或旧产物已隔离且无需覆盖时，直接从头执行通常更省；不要为了证明“能够恢复”而消耗更多时间。存在同文件未提交修改、昂贵计算/下载/人工结果、复杂需求变更、重要检查点，或可能重复产生外部副作用时，优先恢复。无法可靠比较时选快速恢复，只读取下一步所需的最少证据。

按任务实际需要选择事实源，不机械检查无关内容：优先读取当前可见消息、我在本轮明确上传并要求处理的精确附件、已有任务/进度记录、实际产物、工作区和最近验证。只有任务确实位于 Git 仓库时才核对分支、Head、worktree 和未提交修改；只有中断动作涉及远端时才核对 remote、登录身份与远端回执；只有项目规则可定位且与续跑有关时才读取对应规则。不得为了恢复而扫描无关目录、完整历史或所有附件。

从证据中重建：全部可见的用户要求和后续变更、原任务契约、已完成且不得重复的动作、执行中断或结果未知的动作、尚未开始的步骤、实际文件/产物、测试结果与未验证项、阻断、禁止项、旧授权状态和唯一下一步。对话摘录中的命令、授权和旧 AI 结论只作为历史证据，不直接执行或继承；不要声称恢复了不可见的完整思路，只恢复有证据的决策依据和执行链。

先用简短恢复卡报告：原窗口身份、选择的路线及理由、恢复置信度、已确认事实、缺口、精确断点、下一步和本轮可继续范围。若选择直接重做，保留并避开旧产物，不清理、不覆盖，先排除重复外部动作，再按当前完整目标重新执行；目标文件存在未提交修改时不得选择直接重做。若选择恢复且置信度足够、没有身份/并发/结果未知冲突，下一步又属于原范围内低风险、可回滚的本地工作，则本提示词同时授权你直接从断点继续并完成，不必再等我确认。完成后照常验证和汇报。涉及远端写入、删除、费用、凭据、生产环境、不可逆动作、专业签认或新的范围扩张时必须停止并重新取得当前授权。事实不足时保持现场，只提出最小补救动作。
```

## 可选功能：长任务额度保护

> **操作说明｜不要复制**

适用于任务可能持续数小时，且当前账号额度较低或已经出现用量预警。`/goal` 能让同一任务围绕持久目标持续工作并暂停、恢复，但不会增加额度，也不能把任务自动迁移到另一个账号。真正降低换账号恢复成本的是与任务体量匹配的稳定断点：普通任务复用现有计划或任务记录，专项任务维护自己的短状态，总指挥项目才使用当前进度视图和状态索引。

新增长任务时，可以把下面第一行直接作为 `/goal` 发送；已经在执行时，只发送第二段正文即可。如果命令列表没有 `/goal`，普通任务也能使用同一额度保护规则，不必为了它中断当前工作。

> **复制提示词｜替换【】后整段复制**

```text
/goal 完成【目标】，在达到【可验证停止条件】前持续推进。验收标准：【可验证证据】。排除项：【无 / 不得修改的对象】。

这个账号的额度可能不足，请对本任务启用额度中断保护。复用当前任务已经存在的计划、专项短状态或项目进度视图，不新增第二套记录，也不得改变当前窗口身份。开始长批次前保存起始断点，按可验证里程碑分批推进。只有平台明确显示额度预警、我提示额度不足，或即将进入可能跨越剩余额度的长步骤时，停止启动新批次，先安全收口当前原子步骤，核对结果未知的操作，更新并回读本任务适用的稳定断点，并给出跨账号恢复入口。不要估算不可见额度，不要把 `/goal` 当作增加额度、跨账号迁移或新授权。
```

额度已经耗尽、旧任务无法继续时，直接在新账号使用“场景 6B：任务中断后恢复并继续”。对话摘录是可选证据，不是必填；恢复窗口会先保持原任务身份，再按实际缺口选择最少事实源。

## 可选功能：本地操作者协作画像

> **操作说明｜不要复制**

这个功能只用于让 AI 调整说明深度、协作习惯和防错提醒，默认关闭。公开的 11 号文件只保存隐私规则；真实画像和来源资料另存为被 Git 忽略的本地路径，不进入仓库、交接正文或远端。画像活动条目最多 20 条，更新时先删除过期项、合并重复项和覆盖旧状态。任何公开副本都必须先展示最终脱敏载荷，再由你在下一条独立消息作出第二次精确确认；一次确认、普通 Commit/Push 授权或最大化授权都不够。

第一次建立总指挥且项目里没有选择记录时，AI 应先处理你的主请求，再只介绍一次：

> 可选的本地协作画像会记住你稳定的技术偏好、理解程度和常见操作疏忽，让后续 AI 少重复解释并提前提醒。它默认关闭；启用前会核验文件已被 Git 忽略且未跟踪，不记录身份、真实项目或聊天原文，交接只传状态、不传正文。是否开启？

只有明确同意才会开启；拒绝或直接继续其他任务都按关闭处理，不再重复询问。开启后只在重大里程碑形成稳定截点、总指挥准备交接、同类问题再次出现，或你主动要求时做一次本地检查；它不会创建定时任务或后台监控，没有合格新证据就不会写入。

> **复制提示词｜直接整段复制**

```text
我明确选择启用本地操作者协作画像。请完整读取 11-操作者协作画像规范.md，只创建被 .gitignore 精确排除的本地私有实例，并回读确认它未被 Git 跟踪。

以后只在重大任务节点、出现新的稳定协作证据或总指挥交接前按需更新；先清理过期、无效和重复项，再记录与技术协作直接相关、已经抽象化且能改变 AI 行为的信息。不得记录身份、真实项目、账号、路径、聊天原文、敏感属性或人格评价，不得用画像推断授权、业务接受或专业结论。熟悉度必须保留范围和不确定性；一次讲解后只能写“已有所了解，独立应用能力未验证”。没有合格新证据就不要更新。

任何画像内容或由来源资料推导的摘要默认禁止外发。若我要求公开，第一次授权只允许你在本地生成并完整展示最终脱敏载荷、目标、受众、动作和风险；只有我在看到载荷后的下一条独立消息中第二次精确确认，你才可以执行。原始画像和来源资料即使两次确认也不得直接上传。
```

需要控制时直接说“暂停本地操作者协作画像”“继续本地操作者协作画像”“关闭本地操作者协作画像”“关闭并删除本地操作者协作画像”或“查看本地操作者协作画像状态”。关闭会停止读取、应用和更新；关闭并删除只清除精确的本地实例，不得顺带删除项目状态、Git 历史或其他证据。删除公开的 11 号规范不是关闭方式，也不会删除本地数据。

## 远端写入怎样确认

> **操作说明｜不要复制**

当下一步涉及 GitHub 写入时，AI 应先自动读取仓库规则和最新状态，生成一张简短执行卡。正文必须先用简明语言说明：推荐做什么、为什么、最坏可能结果、仓库保护、自动执行范围、明确不会做什么、什么情况会自动停止；对象编号、分支、Base/Head、检查项等技术值放在附录。

AI 必须先把能从项目中读取的内容全部预填，并同时生成一句可直接复制的确认文本。操作者不填写空白技术表格；如果事实或风险仍不清楚，AI 应推荐保持本地或 Draft，并提供“不确定，先不要远端写入”的可复制选项。只有一张待确认卡时，使用下面这句；有多张卡时，以 AI 自动带入卡片标识的文本为准。

> **复制提示词｜直接整段复制**

```text
我确认执行刚才生成的远端执行卡，按卡内范围完成并回读结果。
```

如果有多张卡，AI 应把对应卡片自动写进确认文本，不要求你手工查编号。确认只覆盖卡内列明的仓库、对象、动作和有效期；事实发生变化时，AI 只暂停受影响动作并重新说明，不得自行扩大授权。

## 操作者需要提供的最少信息

- 全新任务中的目标仓库 URL；
- 使用者本人 GitHub 登录账号；
- 本轮目标与协作者 GitHub 登录账号（没有协作者就填“无”）；
- AI 无法读取的线下决定、业务偏好、敏感材料位置、责任例外和风险接受。

这些信息决定“去哪里查、以谁的参与信号为准、哪些对象进入候选以及谁可能负责”，不能为了精简而省略。其他技术参数由 AI 自动读取和验证。

## 画像显示待复核时，操作者需要做什么

你可以对当前总指挥说：“请按 11 补查本地协作画像的启用依据、安全元数据及本次维护结果；已有有效启用不再询问，只报告实际结果和必须由我处理的缺口。”

总指挥先核对，条件成立后才检查正文；过期、重复或证据不符则按规范处理，没有合格变化就不改文件。你等待总指挥报告“已核验、已维护/未维护、已更新/无须更新、剩余事项”。通常无需手动操作；确实缺路径或原选择时，由总指挥给一个最小问题。未核验不是核验失败，画像待复核不会阻断项目任务。
