# 第二代工作流操作者操作手册

本手册告诉你什么时候使用、填写什么、复制哪段，以及成功后应看到什么。AI 的执行细则由其他规则文档维护，你不需要逐份阅读或手工填写技术参数。首次使用直接进入场景 1A，由 AI 自动定位规则目录；无法定位时再提供完整目录路径。

## 快速上手

### Markdown 阅读器

阅读器位于仓库的 `实用小工具/Markdown阅读器/` 目录。双击其中的 `index.html`，点击“打开文档”，选择本文件 `01-操作者操作手册.md`。载入后使用右侧目录搜索或点击“场景一”到“场景七”、可选功能场景及其子场景快速定位；代码框右上角的复制按钮只会复制提示词，不会复制操作说明。阅读器直接读取你选择的原始 Markdown 文件，不会修改或上传文件；保存手册的新版本后，返回阅读器并点击右上角“重新读取当前文件”即可刷新。

### 怎样使用操作手册

每个子场景按“场景标题 → 操作说明 → 复制提示词 → 预期结果”排列：

- **操作说明（不要复制）**：说明什么时候使用、需要填写什么。
- **复制提示词（整段复制）**：只复制代码框中的内容。标注“替换 `【】`”时先填写占位内容；标注“直接整段复制”时无需修改。
- **预期结果**：说明成功后应该得到什么，用于检查 AI 是否真正完成。

`【必填】` 表示执行前必须确定；能从已授权项目中核实的内容由 AI 自动补齐，无法核实的才询问你。`【可选】` 没有特殊情况可以保留“无”或“由 AI 判断”。同一目的只使用一个适用提示词，不把统一入口、专项模板和补充说明重复发送。

以后用自然语言要求新增或修改场景时，AI 应先核对现有编号、归属和相邻场景，再放入唯一对应位置。新增子场景继续使用“操作说明 → 复制提示词 → 预期结果”模板；没有明确要求修改的旧提示词只迁移、不改写，并同步核对编号总表、目录层级、旧锚点和错位引用。

先记住 4 条：

1. 你只需要说清楚目标、偏好，以及 AI 无法从项目中读取的人工决定或线下信息。
2. AI 负责读取项目、GitHub、规则和状态记录，自动判断范围、分支、冲突、测试、责任和下一步。
3. 本地修改、测试和 Commit 可以在已确认范围内连续执行；Push、PR、Comment、Review、Approve、Merge、部署等远端写入，必须在执行前得到你的明确确认。
4. 不确定用哪个场景时直接描述目标。AI 应自动选择或纠正场景；只有不同选择会明显改变范围、风险或结果时，才向你提最少的问题。

你可以直接说目标、描述现象，或说“不知道哪里有问题”，不必先学技术术语或重复审查要求。AI 会核对事实、风险和验证结果；需要你决定时，说明原因并给出最少步骤。你回答“不确定”时，AI 会继续核对，不能把它当作通过。

需要给其他窗口发提示词时，直接告诉当前 AI 你要交接、恢复还是临时分担任务。它会选择适用模板、补齐能核实的信息，并说明提示词应发给哪个窗口。若希望另一个窗口直接执行，明确说出目标与限制；准备提示词、发送消息和取得执行授权是不同动作。

**统一入口：描述目标，由 AI 核对场景**

> **操作说明｜不要复制**

知道想得到什么结果，但不想逐项填模板时使用。填写目标即可，场景可以留空。AI 会从当前可访问的完整规则中核对适用场景，只询问无法自行确认的必要信息。选择场景不会自动改变当前窗口的身份或扩大权限。也可以直接用日常语言说明目的，不必照抄模板、记编号或使用固定说法。确认命中正式场景时，AI 的第一次实质回复应显示“场景判断：场景编号（名称）；依据：简要理由”，并与首个分析或执行说明合并，不单独开启路由回合；这只是路由说明，不代表已经取得授权或完成任务。

> **复制提示词｜填写目标；场景可留空**

```text
我的目标是：【描述希望得到的结果】。
我初步判断适用：【场景名称或编号；不确定可留空】。

请依据随附工作流或当前有权访问的完整规则目录，先核对场景是否适配，再按适用场景执行。我的场景判断仅供参考；若不适配，请简述原因并选择更合适的场景。选择会明显改变范围、风险或交付时，先向我澄清。

能从已授权访问的项目和状态中核实的参数，请自行补齐；不得猜测。缺少会影响范围、结果或权限的信息时，集中向我提出最少的问题，其他安全且不依赖这些答案的工作继续。规则或事实源无法读取时，明确说明缺口。

开始前简短说明所选场景、预期交付和关键待确认项；简单任务不必展开计划。保持原流程的验证标准、角色边界、停止条件和授权要求，不因本入口取得总指挥调度权。模板中的授权示例不代表我的实际授权，不继承旧任务授权。
```

**预期结果：**AI 说明采用哪个场景和交付什么，自行核实可读取的参数，只追问必要缺口，再按原场景执行和验证。你不必重新填写整段专业提示词；这不会降低验证标准，也不保证 AI 每次都能正确选场景。若理解偏离，只需指出“目标或场景理解有误”并补充差异，AI 应重新核对受影响的计划与动作。

**完全不确定时直接这样说**

> **操作说明｜不要复制**

你不需要回忆全部改动，也不要为了填表猜答案。下面这段会让 AI 先保护工作区、恢复客观事实和完成能自动执行的验证；仍需要你观察时，AI 只提供已经准备好的页面、输入和少量选项。`不确定`是合法反馈，但不等于通过。

> **复制提示词｜直接整段复制**

```text
我不确定当前具体修改了哪些内容，也没有可靠的人工验收记录。

请先不要执行远端写入。自动保护当前工作区，从任务记录、Git Diff、未提交、未跟踪、与当前任务有关的忽略文件、依赖、配置、模型、资产和已有验证中恢复修改范围，区分正式候选、无关修改、临时内容和待确认项；不要为了恢复而清理、覆盖或提交来源不明修改。

优先完成能够客观执行的验证。需要人工观察时，把正确页面、输入和最少步骤准备好，只让我选择“符合预期 / 不符合预期 / 不确定”。请同时给出可直接复制的示例回答，不要让我填写技术字段。证据仍不足时保留本地候选或 Draft，不要宣称已经通过，也不要执行 Push、PR、Comment、Review、Merge 或其他远端写入。
```

### 首次使用

1. 把本工作流下载或克隆到一个稳定的本地目录。
2. 在 Codex Desktop 中打开真正要开发或管理的目标项目；不要打开本规则仓库，除非你正在维护规则本身。
3. 使用场景 1A 建立总指挥。AI 会先自动定位完整规则目录；只有无法定位时，才需要你提供规则文件夹路径。

本工作流当前直接适用于 GitHub；其他托管平台需要先适配平台能力和授权规则。

## 场景一：工作流生命周期

### 场景 1A：首次启动或恢复总指挥

> **操作说明｜不要复制**

在全新的总指挥任务中使用。必填远端仓库 URL 和本人 GitHub 登录账号；规则目录通常保留“自动定位”，只有 AI 无法定位或规则文件夹已经移动时才填写完整路径。

> **复制提示词｜替换【】后整段复制**

```text
远端仓库地址：【必填：完整 GitHub 仓库 URL】
使用者本人 GitHub 登录账号：【必填：GitHub 用户名，不是显示昵称】
第二代规则目录：【自动定位 / 规则文件夹绝对路径】

请在当前项目建立或恢复唯一总指挥。先核对当前本地项目的 Git remote 与上面的远端仓库、当前实际登录账号与填写账号是否一致，再读取项目规则、状态记录、代码、Git 和 GitHub 当前事实。只读确认项目范围、当前目标、已完成事项、活跃工作、工作区状态、远端状态、阻断和下一步。

判断这是首次启动、正常恢复、目标变化还是控制面冲突。本轮先不要修改产品、不要创建重复状态记录，也不要执行远端写入。规则入口无法定位时，只向我索要一次规则文件夹路径。仓库不一致时只暂停受影响的仓库动作并说明差异，不要猜测或修改 remote。
```

**预期结果：**AI 按该提示词完成本场景动作，并汇报实际执行、验证结果、未完成项和下一行动方。
### 场景 1B：换新聊天或归档前准备续接材料
> **操作说明｜不要复制**

当你表达以下目的时，AI 应自动执行连续性检查，不要求你先找到场景编号：正式更换总指挥；当前聊天已经混入较多支线，想把未完成主线移到新聊天；准备归档当前对话。AI 会先核对当前角色、活跃请求、正在执行或结果未知的动作、未提交成果和下一步，再提供至少一种可续接材料。

- 正式更换总指挥：使用场景 1C 生成便携交接快照，再按场景 1D 分阶段切换。
- 普通任务或不转移总指挥权的分支：生成一段可直接发给新窗口的精简续接提示词；只有你明确要求继承当前已完成历史时才使用 Fork。
- 归档仍承担工作的总指挥：先走场景 1C；归档普通或专项任务：先生成精简续接提示词。已经没有未完成事项时，AI 明确说明“无待续任务”，不制造空任务。

精简续接提示词至少说明：原窗口身份、当前目标、已完成且不得重复的动作、正在执行或结果未知的动作、实际产物与验证、未提交修改和进程、阻断与禁止项、旧授权不继承、精确断点、下一动作、证据入口和失效条件。AI 能核实的内容自动填写，不让你查任务 ID 或拼接聊天记录。

如果由 AI 创建新任务，它应把同一份精简材料写进新任务的初始提示，并向你显示可人工补发的版本；只有目标窗口没有收到或无法定位时才使用补发文本，避免重复执行。仅创建成功、Fork 成功或归档成功都不能代替新窗口对断点的回读确认。

> **复制提示词｜直接整段复制**

```text
我准备把当前未完成工作移到新对话继续，或在归档前保存续接材料。请先核对当前角色和全部活跃请求，在安全原子边界停止；区分已完成且不得重复、正在执行或结果未知、尚未开始和已经取消的事项。

正式总指挥换任请转入场景 1C 和 1D；其他情况请生成一段可直接发给新窗口的精简续接提示词，自动填写当前目标、事实与工作区基线、产物和验证、未提交修改与进程、阻断、禁止项、旧授权不继承、精确断点、下一动作、证据入口和失效条件。没有待续任务时明确说明，不创建空任务。未经我明确要求，不创建、Fork、归档或发送消息。
```

**注意：**如果你直接在 Codex 侧栏点击“归档”，当前 AI 可能收不到这个操作，因而无法提前生成材料。仍有工作要继续时，先在对话里说“准备归档，请先整理续接材料”，拿到提示词或快照后再归档。

**预期结果：**AI 按该提示词完成本场景动作，并汇报实际执行、验证结果、未完成项和下一行动方。
### 场景 1C：旧总指挥准备移交身份

> **操作说明｜不要复制**

在旧总指挥中使用。它也是总指挥归档前的必经入口。旧总指挥会生成交接快照，但不会自行停止，也不会提前启动新总指挥。

**无论有没有 Commit，都只需复制下面这一段提示词。** 未提交成果是默认交接范围，不需要先发补充提示词，也不默认创建专项任务。交接快照是接手说明和证据入口，不是自动携带全部代码的备份包：

- **同一电脑、同一工作目录接手：**已保存到磁盘的修改和必要新文件保留原位，下任按清单读取实际文件与验证证据，不要求为了交接先 Commit。
- **换工作目录、worktree 或电脑：**必须先恢复必要成果，只有快照或 `git pull` 不够。把接手位置的变化告诉旧总指挥，由它核对现有授权并准备最小恢复方案；打包、跨机传输及覆盖另按权限处理，未恢复时不能宣称成果已交接。
- **编辑器还没保存：**在编辑器中保存本次修改，再让旧总指挥重新核对。预期文件出现在磁盘、交接清单反映最新内容；保存失败时提供错误文字和受影响文件，不要关闭仍含未保存内容的编辑器。AI 未取得编辑器内容时只能标记未知，不能从 Git 推断“全部已保存”。

> **复制提示词｜直接整段复制**

```text
请准备总指挥交接。先安全收口当前原子步骤，并只读检查是否存在未核验的高风险动作、未记录断点、重复调度、事实冲突或不可靠的完成声明。必要时压缩当前进度视图，但不得删除原始证据或破坏回查入口。

默认保留本轮最新成果，包括已保存但未 Commit 的修改、暂存区与工作区差异、删除/重命名、必要未跟踪文件及获准访问的必要依赖和资产；按 04“成果连续性与运行复现契约”核对，不为交接强制 Commit、清理或换工作区。同机同工作区保留原位；接手位置改变时先准备获准的恢复方式，不能把交接快照或 git pull 当作未提交文件已经传到目标。编辑器未保存内容不可见时标为待确认，提示我保存后复核；缺少权限或必要文件时只暂停依赖它的接续。

生成一份精简、可验证的交接快照，记录：事实截点、当前与暂停目标、代码/工作区/远端基线、活跃工作及逐对象状态、已完成证据、未提交成果、阻断和当前行动方、禁止项、下一步、恢复/失效条件、第一次只读动作和详细证据入口；同时记录轻量交接启动配置及 02、04、07、09、10 的来源指纹。

在已有受控记录中保留接续必需的成果清单和详细证据入口，覆盖修改目的、当前实现与关键决策、已验证/未验证项及精确断点。逐项说明文件保留或恢复位置、内容核验方式以及新候选应回读的实际代码、配置和测试；快照正文只引用它们，不以一句“有未提交修改”代替。候选未取得必要材料或尚未核对实际成果时，不宣称该部分已经可靠接续。未经明确授权，不自动创建、归档或向其他任务发送材料。
```

### 场景 1G：任务意外中断后恢复并继续

> **操作说明｜不要复制**

适用于任何普通、专项或总指挥任务因为额度耗尽、程序异常、账号切换等原因中断后，在新窗口恢复现场。它不会把普通任务或专项任务升级为总指挥。原窗口仍能继续时，直接说“从断点继续”；旧总指挥还能正常生成正式交接时，优先使用场景 1C 和 1D。

```text
当前任务因【额度耗尽 / 程序异常 / 账号切换 / 其他原因】中断。请恢复这个窗口原本承担的任务，并从可靠断点继续完成；不得因为本提示词而改变身份、扩大职责或把普通/专项任务升级为总指挥。

在展开长对话、完整日志、全仓历史或中央状态前，先执行恢复收益门禁，只用当前消息、任务身份、现有产物/工作区摘要和结果未知信号判断路线：`直接重做 / 快速恢复 / 深度恢复 / 必须先核账`。简单且可确定重现、当前消息已包含完整目标、没有值得复用的中间成果或未核验外部动作，并且目标工作区洁净或旧产物已隔离且无需覆盖时，直接从头执行通常更省；不要为了证明“能够恢复”而消耗更多时间。存在同文件未提交修改、昂贵计算/下载/人工结果、复杂需求变更、重要检查点，或可能重复产生外部副作用时，优先恢复。无法可靠比较时选快速恢复，只读取下一步所需的最少证据。

```

## 跨场景操作：让其他 AI 临时分担任务

> **操作说明｜不要复制**

总指挥正在处理其他工作，需要新 AI 临时分担一个独立工作项时使用。这个工作项可以尚未开始，也可以已经完成一部分；这不是场景 1D 的正式总指挥换任，当前总指挥仍负责统一调度和最终收口。

通常只需填写任务目标。新 AI 如果位于同一项目，应先自行核对项目根目录、仓库规则、当前文件和 Git 状态；不要因为处于同一项目就假定已经掌握最新进度。只有无法定位正确项目、存在多个候选仓库或需要读取项目外材料时，才补充本地路径、远端地址、附件或证据入口。任务已经做过一部分时，再提供已知断点；不清楚断点也可以让新 AI 根据实际文件和记录核验。

> **复制提示词｜替换【】后整段复制**

```text
你是当前项目的临时执行者，不接替总指挥。请分担这个工作项：【必填：任务目标、范围和期望结果】。

当前进度或断点：【选填：尚未开始／已完成到哪一步／不清楚，请根据实际文件和记录核验】
必要材料：【选填：当前项目内自行定位／精确文件路径／附件／远端仓库或其他证据入口】

结束时返回一份简短结果卡：实际完成、修改对象、验证及结果、未验证项、未完成项、阻断、证据入口、下一建议，以及建议由总指挥核验写回的最小状态增量。不要生成或更新总指挥交接快照。
```

**预期结果：**新 AI 能从零开始或从已核验断点继续分担明确工作，并把可核验结果交回总指挥收口；无需虚构交接快照，也不会因分担任务取得总指挥权、中央状态写入权或额外远端权限。

## 场景四：合作维护远端仓库（以 GitHub 为例）

本大类的子场景固定按以下顺序理解：**4A 提交/更新 PR → 4B 单独处理 PR → 4C 根据 Issue 生成 PR → 4D 汇报进展 → 4E 收口过时对象 → 4F 全量接管队列 → 4G 增量推进与覆盖核账 → 4H 长期未提交远端变更的兼容准备 → 4I 按需安全汇合双方成果**。

本大类处理 GitHub 上的 PR、Issue、协作队列和发布前同步。所有远端写入仍按单独确认卡执行。

### 场景 4A：单独提交一个 PR

> **操作说明｜不要复制**

已有本地分支或工作区成果，需要先整理成一个可供预览的 PR 时使用。AI 先核对差异、测试、隐私和关联对象，只在本地准备草稿；远端创建、Push 和请求审阅仍需单独确认。

> **复制提示词｜替换【】后整段复制**

```text
请为【本地分支/工作区】准备一个 PR。先核对 Base、Head、差异、测试、隐私、关联 Issue、Reviewer 和仓库规则，判断是否存在重复 PR 或不应提交的文件。先生成标题、说明、变更—验证矩阵和远端执行卡；默认只在本地准备，未获逐卡确认不得 Push、创建 PR 或请求审阅。
```

**预期结果：**得到可预览的 PR 草稿、差异与验证矩阵；没有对应确认前不改变远端。

### 场景 4B：单独处理一个 PR

> **操作说明｜不要复制**

> **复制提示词｜替换【】后整段复制**

```text
请只审阅 PR【链接或编号】。先读取 PR 描述、Base/Head、完整 Diff、相关代码、测试和仓库规则；按设计、功能、边界、安全/隐私、兼容性、复杂度、文档和验证证据检查。按阻断问题 / 建议修复 / 可接受风险分级，给出具体文件与依据。默认只生成本地审阅报告，不发表评论、不批准、不合并。
```

**预期结果：**得到按优先级分级的审阅报告和下一步建议；远端状态保持不变。

#### 兼容正文：场景 4B（回复审查意见并再次请求审阅）

> **操作说明｜不要复制**

### 场景 4E：审查并收口明显过时的 Issue/PR

> **操作说明｜不要复制**

> **复制提示词｜替换【】后整段复制**

```text

- 有权限且达到关闭门禁：列出精确 Close 动作和拟发布的简短说明，等待我明确点名确认要关闭的编号；未被点名的候选继续保持开放。
```

```text
请对上述目标的当前 GitHub 协作队列执行增量推进与覆盖核账。先加载 4F/4G 及远端授权规则，再核对本地仓库 remote、远端 URL、当前登录身份和填写账号。自动恢复并验证最近可靠截点，明确说明从哪个截点开始；截点缺失、失效、数量矛盾、范围或身份变化、任务中断、事实冲突或怀疑遗漏时，暂停增量并转为 4F 全量核对，不要求我查询历史 ID。

只读取自该截点以来新增或变化的 Issue/PR、Comment/Review/Commit/Push/状态变化、未闭环旧账、派生对象和最小依赖；不得只扫描新编号，也不得重复已有有效回执的动作。第一阶段只读生成逐对象执行卡，说明纳入/排除依据、本轮变化、建议动作、风险、验证、禁止项、失败回退和交棒终点；不改产品代码，不执行远端写入。

收到我一次集中确认后，连续推进卡内已授权且不受阻的对象；单项受阻只暂停该项。结束时回读受影响对象和未闭环旧账，完成覆盖及结束差集核账，保存下一可靠截点，并分别报告本地完成、远端可见、待确认回执、遗漏/排除、当前行动方和我的必要人工操作。
```

**预期结果：**AI 能证明“从哪个可靠截点开始、这次新增或变化了什么、有没有漏项”；截点不可信时会自动转全量。

### 场景 4H：长期未提交远端变更的兼容准备
> **操作说明｜不要复制**

本场景用于本地长期未提交远端时，先查询远端变化及其对本地开发的影响，提前识别潜在冲突，并在隔离位置做不影响主线的预处理。它不替代继续开发，也不自动合并或发布；真正需要把双方成果合到一起时转到场景 4I。
**4H 和 4I 的区别：**4H 是“先看远端变了什么、会不会影响本地，并提前准备”；4I 是“确认双方都有需要保留的成果后，制定并执行安全汇合方案”。4H 不要求两边已经分叉，4I 也不因等待时间长而自动触发。

> **复制提示词｜替换【】后整段复制**

```text
请为长期未提交远端的【本地功能/工作项】做兼容性准备。先只读核对当前本地基线、工作区、未提交修改、远端默认分支及其新增提交、关联 Issue/PR 和仓库规则，说明远端变化对本地开发的影响，区分无影响、可提前处理、可能冲突和已发生冲突。必要时只在隔离分支或 worktree 生成补丁、冲突清单或预处理建议，不改变本地开发主线，不替代人工验收，不自动合并、发布或 Push。最后给出是否需要进入 4I 安全汇合、候选方案、验证点、回滚方式和下一行动方；所有 Fetch、Merge、Rebase、Cherry-pick、Commit、Push 或远端写入均须另行确认。
```

**预期结果：**AI 按该提示词完成本场景动作，并汇报实际执行、验证结果、未完成项和下一行动方。

### 场景 4I：按需安全汇合双方成果

> **操作说明｜不要复制**

**4I解决的是“两边成果怎样安全合到一起”。**例如本地改了一个功能，队友在远端也提交了需要保留的修改；可以单独要求先汇合，也可以在场景 2 准备交付时让 AI 识别这一步。它会先检查事实、保留现有成果，再把具体操作交你确认。只想继续改功能或准备发布时，从场景 2 进入即可。

4I可由场景 2 调用，也可按独立同步目标使用；它只处理确有必要的成果汇合，不是另一套开发或发布流程。“长期未同步”只提示核查，不是触发条件。双方都有尚未包含于对方、且需保留的有效成果，并且当前目标确实需要汇合时，才准备实际汇合方案。关系不明先只读核对，不预设 Merge；单侧更新按目标处理，不自动进入 4I。

具体判断只维护在 [02 共用只读路由](02-总指挥核心规则.md#发布与同步的共用只读路由)，冲突处理沿用 02 的安全汇合执行段。旧“本地与远端长期分叉后的安全同步”名称、编号和链接继续可用，只用于定位并按当前事实重新判断，不产生汇合或发布授权。

> **复制提示词｜替换【】后整段复制**

```text
远端仓库地址：【可选：自动读取当前 remote / 完整仓库 URL】
同步目标：【可选：安全汇合双方最新有效成果 / 自然语言说明】
必须保留或排除的内容：【可选：由 AI 自动识别 / 自然语言说明】

请按场景 4I“两边都有改动时，安全汇合成果”及02共用只读路由核对当前项目。仅当本地与远端、两个分支或两个工作区各有需要保留的有效改动时使用本场景。先保留现有工作区，判断目标、双方有效成果、未提交增量、共同祖先和归属。远端只读查询、Fetch与工作区/历史变更分别核对权限；本轮默认只读，不新增功能、不替代人工验收、不准备发布，也不因本提示词自动 Fetch、Merge、Rebase、Cherry-pick、Commit、Push 或 PR Merge。完成后返回基线、冲突、候选整合方案、新验证点和下一行动方。

确需汇合时，复用当前工作项与本地执行卡，预填最小汇合方案；没有现有卡才创建必要的本地卡。Merge、Rebase、Cherry-pick、分支/worktree、Commit等动作须获对应确认，不让我选择 Git 技术参数，不把冲突整体判给某一侧。完成后按新基线复核受影响证据：原目标含发布时回原发布候选并更新同一有效远端卡；只更新本地时按该目标收口，不要求创建PR。
```

**预期结果：**AI 先说明是否需要汇合、依据、风险和当前行动；经对应确认才改变本地状态。若无需汇合，直接回到原目标；事实变化只使受影响方案、验证和旧授权失效，不重开整套流程。

## 场景五：AI 交叉检查（执行者＋审查者模式）

兼容旧称：“场景五：一个 AI 负责执行，另一个 AI 独立检查（2～3 轮后收口）”。

支持内部子 Agent、独立任务窗口或混合配对。一个 AI 负责执行，另一个不同的 AI 独立检查。开始前先查当前项目中是否已有同一工作项、同一范围的执行者和审查者；已有且仍可访问、契约有效、没有冲突时直接复用，不新建窗口或子 Agent。总指挥只补充既有配对没有的关键决策、约束和证据，不搬运完整聊天。没有合适配对时，才建立最小配对。

当一个 AI 正在执行任务，但你担心它漏掉细节、方向偏了或加入了无效内容时，使用本场景。执行者产出并修订，独立审查者只检查和复核，通常 2 轮，只有预先允许或出现新证据时才进行第 3 轮。普通“请你自查一下”仍由当前 AI 自检，不建立配对；“AI 交叉检查”或“审查者模式”才进入本场景。
普通自检或只读解释不自动建立配对；只有明确需要两个不同 AI 实例交换意见并复核时，才使用本场景。你说“让 AI 交叉审查”或“审查者模式”时，默认进入本场景。
只说“对抗式审查”“你再自查一下”默认由当前 AI 做结构化自审，不额外创建执行者或审查者。
只询问或讨论 2F 时不启动配对；旧编号仅用于兼容历史入口。

配对只传最小必要上下文：共同契约和规则指针只发送一次，执行者接收实现基线与允许写入范围，审查者接收原始要求、验收标准和关键证据；后续只发送成果版本、差异、意见编号和证据指针。稳定前缀保持不变，避免重复粘贴规则、完整日志和整段聊天。这样只能提高缓存复用的可能性，不能保证平台一定命中缓存。

默认只用一名独立审查者。能用脚本、测试、解析器或哈希确定的事实先由确定性工具核验；审查者集中检查最可能改变结论的证据、边界和反例。无实质问题时首轮结束；有问题时修订后只复核改动及受影响回归，不为“意见一致”继续讨论。高影响工作仍可按主规范完整审查，不能为了省 Token 降低必要验证。

**建立、切换或不知道找谁时，发给当前负责安排的 AI；项目已有总指挥时优先发给总指挥。**内部助手的反馈也发给该 AI，由它转交，你无需寻找助手窗口。下文“执行窗口”指可直接联系的独立任务；内部或混合方式由收口方说明唯一反馈入口。

建立配对后，执行 AI 负责产出和修改，独立检查 AI 负责指出问题并复核；两者不是两个总指挥，项目仍只有一个中央调度者和单写者。默认每批最多 2 轮；只有契约预先允许或出现新的可验证证据时才启用第 3 轮，第 3 轮后必须结束本批。收口不需要单独选择场景，满足通过、无实质问题、达到上限或明确阻断任一条件即可结束。

| --- | --- | --- | --- |

专项执行者或独立审查者完成一阶段并把结果交给总指挥后，只能把下一步作为候选建议，不能同时要求你执行；它会明确告诉你现在不用操作、候选是“已确认接收”“已发送待确认”还是“尚未送达”。下一阶段需要你操作、授权、选择或验收时，由总指挥统一给出当前有效行动。你不需要填写任务 ID、版本或内部字段。收口方必须说明是沿用还是替代阶段行动方建议，并只给一个“现在立即做什么”或明确说明“现在不要操作”。
你直接发给专项窗口、仍属于当前阶段且不冲突的明确指令照常有效，不需要重复授权；不冲突的只读核验也可以继续。

下列代码框可直接复制；只需替换工作项和反馈内容，版本、轮次、窗口身份及技术参数由 AI 核实。详细角色职责、转交和返工规则见 [协作规范](docs/EXECUTION_AND_INDEPENDENT_REVIEW.md)。

### 场景 5A：建立“执行 AI＋独立检查 AI”配对｜发给当前负责安排的 AI

> **操作说明｜不要复制**

> **复制提示词｜替换【】后整段复制**

```text
我要开展【工作项】，目标是【用途与预期结果】。请先检索当前项目中已有的同一工作项、同一范围的执行者和独立审查者，包括现有专项任务窗口、内部子 Agent 及其短状态；核对角色、契约版本、成果版本、可访问性、当前轮次和是否仍在工作。已有配对仍有效且无冲突时直接复用，不新建专项任务或子 Agent；如果只找到一方或状态已失效，说明原因后只补建缺失角色，不复制已有角色。

如果总指挥曾经亲自参与但既有配对没有这些信息，请先让总指挥提供最小上下文增量：已确认决策及证据指针、被否决方案及原因、当前约束、未提交成果、未决问题和精确断点；不要搬运完整聊天或重复规则。若工作项尚未开始，则只提供目标、范围、验收和必要基线。

请建立或复用“一个 AI 执行、另一个不同 AI 独立检查”的最小配对，并让双方确认共同契约、检查范围、验收标准、每批最多两轮及第 3 轮的启用条件。共同契约和规则只传一次，后续交棒只传成果版本、差异、意见编号和证据指针。执行 AI 负责产出和修改，独立检查 AI 只读检查、提出依据和复核结果，不能由同一实例冒充独立审查。

我的普通反馈直接发执行者；允许范围内的工作不需逐次中转。存在项目总指挥时保持其中央调度与单写权唯一，其他总指挥只承担本工作项角色。第一阶段仅做配对核验、方案和独立审查，不改产品、不运行模型或高资源验证、不写远端；由 AI 自动填写身份、契约、基线、验收、轮次、路由和停止条件，无法核实的事项集中向我提最少问题。需要实施时给我具体范围与验证方案，等我确认。
```

操作：只发给当前负责安排的 AI；项目有总指挥时优先发给总指挥。等待它说明实际协作载体、各自职责、收口方和你应联系的入口；如要实施，在它给出的具体任务包上确认。预期：双方知道彼此和汇报对象，按允许范围完成工作。异常：无法创建或联络时，由收口方给最小人工替代步骤；不自行建重复窗口或 Fork。

**预期结果：**双方确认执行者、独立检查者、收口方、检查范围和轮次；需要实施时再按确认后的任务包继续。

> **操作说明｜不要复制**

> **复制提示词｜替换【】后整段复制**

```text
我想调整当前工作，具体想法随本消息说明。请先核对与已有任务、成果和权限的关系，能继续复用就复用；需要新目标或额外权限时给我具体方案。不要仅因我提出想法就创建新任务、运行高资源验证或写远端。
```

**预期结果：**按当前配对契约完成本场景动作，并明确下一行动方、验证和阻断。

## 场景七：跨场景通用能力

### 场景 Gen1：长任务 Token 保护

> **操作说明｜不要复制**

适用于任务可能持续数小时，且当前账号额度较低或已经出现用量预警。`/goal` 能让同一任务围绕持久目标持续工作并暂停、恢复，但不会增加额度，也不能把任务自动迁移到另一个账号。真正降低换账号恢复成本的是与任务体量匹配的稳定断点：普通任务复用现有计划或任务记录，专项任务维护自己的短状态，总指挥项目才使用当前进度视图和状态索引。

新增长任务时，可以把下面第一行直接作为 `/goal` 发送；已经在执行时，只发送第二段正文即可。如果命令列表没有 `/goal`，普通任务也能使用同一额度保护规则，不必为了它中断当前工作。

> **复制提示词｜替换【】后整段复制**

```text
/goal 完成【目标】，在达到【可验证停止条件】前持续推进。验收标准：【可验证证据】。排除项：【无 / 不得修改的对象】。

这个账号的额度可能不足，请对本任务启用额度中断保护。复用当前任务已经存在的计划、专项短状态或项目进度视图，不新增第二套记录，也不得改变当前窗口身份。开始长批次前保存起始断点，按可验证里程碑分批推进。只有平台明确显示额度预警、我提示额度不足，或即将进入可能跨越剩余额度的长步骤时，停止启动新批次，先安全收口当前原子步骤，核对结果未知的操作，更新并回读本任务适用的稳定断点，并给出跨账号恢复入口。不要估算不可见额度，不要把 `/goal` 当作增加额度、跨账号迁移或新授权。
```

额度已经耗尽、旧任务无法继续时，直接在新账号使用“场景 1G：任务意外中断后恢复并继续”。对话摘录是可选证据，不是必填；恢复窗口会先保持原任务身份，再按实际缺口选择最少事实源。

### 场景 Gen2：暂停正在运行的任务并存档

> **操作说明｜不要复制**

任务正在运行但需要临时停止、以后从断点继续，或交给其他任务接手时使用。先检索本地是否已有适合的存档文件；存在则更新并回读，不存在时只有确实需要持久化且符合当前授权才新建。若仓库已有研发计划、研发进度或 CHANGELOG，则按实际文件名更新；没有现成文件时不为了暂停强行创建。

> **复制提示词｜直接整段复制**

```text
请暂停当前工作并保存可恢复断点。先检索本地是否已有适合的存档、状态或研发进度文件；有则在当前授权范围内更新并回读，没有则说明缺口，不要为了暂停强行新建。记录当前目标、范围、已完成与已验证事项、未完成项、未提交修改、结果未知动作、阻断、恢复条件和下一步，并把实际访问路径告诉我。不要删除任务、分支、worktree、文件或历史，不要启动新的远端写入。若已有 CHANGELOG、研发计划或研发进度文件，只按其原有格式补充必要状态；暂停完成后告诉我下次恢复的第一步只读检查。
```

少量截图直接发给总指挥。只有大量图片会明显污染长会话且结构化摘要足以支持后续工作时，AI 才应建议独立的只读视觉观察任务；这不是操作者日常需要选择的场景。结束图片轮次、附件冷存储和上下文健康检查由 AI 自动处理，删除原件仍需单独确认。

## 可选功能场景：个性化协作

### 可选功能 Pe1：操作者画像（Personalization）

> **操作说明｜不要复制**

这个功能只用于让 AI 调整说明深度、协作习惯和防错提醒，默认关闭。公开的 11 号文件只保存隐私规则；真实画像和来源资料另存为被 Git 忽略的本地路径，不进入仓库、交接正文或远端。画像活动条目最多 20 条，更新时先删除过期项、合并重复项和覆盖旧状态。任何公开副本都必须先展示最终脱敏载荷，再由你在下一条独立消息作出第二次精确确认；一次确认、普通 Commit/Push 授权或最大化授权都不够。

第一次建立总指挥且项目里没有选择记录时，AI 应先处理你的主请求，再只介绍一次：

> 可选的本地协作画像会记住你稳定的技术偏好、理解程度和常见操作疏忽，让后续 AI 少重复解释并提前提醒。它默认关闭；启用前会核验文件已被 Git 忽略且未跟踪，不记录身份、真实项目或聊天原文，交接只传状态、不传正文。是否开启？

只有明确同意才会开启；拒绝或直接继续其他任务都按关闭处理，不再重复询问。开启后只在重大里程碑形成稳定截点、总指挥准备交接、同类问题再次出现，或你主动要求时做一次本地检查；它不会创建定时任务或后台监控，没有合格新证据就不会写入。

> **复制提示词｜直接整段复制**

```text
我明确选择启用本地操作者协作画像。请完整读取 11-操作者协作画像规范.md，只创建被 .gitignore 精确排除的本地私有实例，并回读确认它未被 Git 跟踪。

以后只在重大任务节点、出现新的稳定协作证据或总指挥交接前按需更新；先清理过期、无效和重复项，再记录与技术协作直接相关、已经抽象化且能改变 AI 行为的信息。不得记录身份、真实项目、账号、路径、聊天原文、敏感属性或人格评价，不得用画像推断授权、业务接受或专业结论。熟悉度必须保留范围和不确定性；一次讲解后只能写“已有所了解，独立应用能力未验证”。没有合格新证据就不要更新。

任何画像内容或由来源资料推导的摘要默认禁止外发。若我要求公开，第一次授权只允许你在本地生成并完整展示最终脱敏载荷、目标、受众、动作和风险；只有我在看到载荷后的下一条独立消息中第二次精确确认，你才可以执行。原始画像和来源资料即使两次确认也不得直接上传。
```

需要控制时直接说“暂停本地操作者协作画像”“继续本地操作者协作画像”“关闭本地操作者协作画像”“关闭并删除本地操作者协作画像”或“查看本地操作者协作画像状态”。关闭会停止读取、应用和更新；关闭并删除只清除精确的本地实例，不得顺带删除项目状态、Git 历史或其他证据。删除公开的 11 号规范不是关闭方式，也不会删除本地数据。

## 操作者需要提供的最少信息

- 全新任务中的目标仓库 URL；
- 使用者本人 GitHub 登录账号；
- 本轮目标与协作者 GitHub 登录账号（没有协作者就填“无”）；
- AI 无法读取的线下决定、业务偏好、敏感材料位置、责任例外和风险接受。

这些信息决定“去哪里查、以谁的参与信号为准、哪些对象进入候选以及谁可能负责”，不能为了精简而省略。其他技术参数由 AI 自动读取和验证。

## 画像显示待复核时，操作者需要做什么

你可以对当前总指挥说：“请按 11 补查本地协作画像的启用依据、安全元数据及本次维护结果；已有有效启用不再询问，只报告实际结果和必须由我处理的缺口。”

总指挥先核对，条件成立后才检查正文；过期、重复或证据不符则按规范处理，没有合格变化就不改文件。你等待总指挥报告“已核验、已维护/未维护、已更新/无须更新、剩余事项”。通常无需手动操作；确实缺路径或原选择时，由总指挥给一个最小问题。未核验不是核验失败，画像待复核不会阻断项目任务。
