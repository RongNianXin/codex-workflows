# 总指挥轻量交接启动配置

版本：2026-09-05.4

用途：作为 `01-操作者操作手册.md`“场景 6A：新总指挥接收正常交接”的唯一轻量启动配置。它只覆盖“新总指挥候选”的第一次只读核验和最终切换前复核，不授权产品实现、远端写入、删除、费用、部署或新调度。

本配置具有独立的加载价值，但不是新的编号规则。`04-状态、目标变更与交接规范.md` 负责交接契约，`10-自动状态索引规范.md` 负责指纹和加载记录；本配置负责把候选阶段必须立即生效的规则收敛成最小完整集合。系统/平台限制、当前团队与仓库规则始终优先。

## 1. 适用与加载门禁

1. 只适用于：旧总指挥仍可确认、已有稳定正式快照、操作者明确指定“新总指挥候选”的场景 6A 正常交接。场景 6B 是角色中立的任务中断恢复入口，不加载本配置；它先恢复原窗口身份，普通或专项任务只读取自身适用规则，只有确认属于无正式总指挥交接时才按 02、04、09、10 的对应章节恢复中央控制面。快照不可靠或无法确认单写者时不得套用轻量候选路径。
2. 新候选必须自行完整读取本配置，并建立本任务独立加载记录；不得继承旧任务的“已读”声明。加载记录至少包含配置路径、版本、大小、修改时间、SHA-256、来源规则清单比对结果和加载时间。
3. 快照必须记录本配置的相对路径、版本、SHA-256，以及交接时 02、04、07、09、10 的路径和 SHA-256。候选重新计算并比对；全部一致时，候选阶段不再全文读取这五份编号规则。
4. 任一编号规则指纹变化时，只完整读取受影响文件并记录差异；配置缺失、配置指纹不一致、规则根目录冲突、来源清单不完整或无法判断影响范围时保持只读，退回完整规则加载。不得用旧任务记录、附件同名、Prompt Cache 或摘要代替本任务加载。
5. 旧格式快照没有本配置字段时，不自动享受轻量路径。只有当前候选任务已经自行完整读取旧版适用规则，并在同一任务内完成本次规则更新或核验时，才能记录一次过渡加载；其他任务必须退回完整加载。
6. 正式切换后，执行任何未由本配置完整定义的动作前，按实际场景加载所需编号规则和当前团队/仓库规则。指纹一致只允许避免候选阶段的固定全文读取，不构成后续动作授权。

## 2. 不可压缩的硬门禁

- 候选阶段只读：不得终止旧总指挥、取得中央调度权或主执行权、修改中央状态、修改产品代码、Commit、Push、执行其他远端写入、删除证据，或启动新的全量、增量、专项调度。
- 候选核验完成前，旧总指挥保持唯一中央写入者，候选只能形成候选截点和建议状态增量。操作者停止或归档旧总指挥后进入短暂无写者窗口；候选只有在最终确认、最小复核和中央原子更新成功后才成为唯一写者。
- 旧远端授权、运行中进程、完成声明、专业/人工结论和旧任务规则加载状态一律不继承；当前事实必须按最小范围回源。
- 本地操作者协作画像不属于候选阶段的事实源或授权源。候选只核对 `unasked / enabled / paused / disabled / unavailable`、一次介绍状态、最近节点维护结果、通用相对指针、schema、过期、容量和 Git 排除状态，不读取或复制画像正文、来源资料、内容哈希、外发载荷或确认原文；缺失、未更新、到期或校验失败只禁用协作适配，不阻断交接，旧世代的任何画像外发确认一律失效。候选阶段不得询问是否启用；正式接管后只有 `unasked` 才在首个主回复末尾介绍一次。
- 已有可靠完成凭证的任务不得重复执行。发现漂移只标记受影响范围、证据和最小补救动作。
- 候选报告“达到可切换条件”不等于已经接管。操作者必须先停止或归档旧总指挥，再明确发送最终切换确认；候选不得代替操作者终止旧任务。
- 最终确认到达后，候选先复核配置/来源指纹、中央世代与单写者、快照失效条件、工作区指纹、当前 Head/状态计数和远端基线。仍可靠时才原子更新中央入口、当前进度视图和 AI 状态索引，并立即回读；存在冲突时不得切换。
- 总指挥世代编号不得复用。中央回读确认唯一写者前，不得宣布交接完成。
- 切换尝试结束后按本配置第 7 节的唯一模板发送独立最终回复；交接语义与权限仍以 `04-状态、目标变更与交接规范.md` 为准。候选核验不等于切换；新规则不得追溯证明旧结论。

## 3. 第一次只读的最小读取链

按顺序读取并在获得结论后停止扩展：

1. 便携交接快照；
2. 项目规则入口与更近的团队/仓库规则；
3. 当前进度视图的当前目标、断点、禁止项、失效条件和证据指针；
4. `AI状态索引.md` 的当前指针、总指挥世代、最近交接记录和规则加载记录；协作画像只读取五态、一次介绍状态、节点维护结果与安全指针，不读取正文；
5. 当前唯一活跃任务的主执行阶段、唯一产品写者、例外专项任务及其隔离边界和完成凭证；
6. 耐久 Commit 台账的最后核账截点、当前相关 `KEY_NODE` 及原提交到当前提交的映射；
7. 当前工作区、Git/平台基线、目标候选、并存实现决议、规范启动命令及自检输出、实际运行选择器、模型/资产、运行进程和证据入口的低成本事实抽查。

快照中的仓库内规则、模板和证据指针必须按当前仓库根目录解析相对路径。仓库克隆、移动或换盘后，旧机器绝对路径只作为已失效的实例诊断信息；候选先验证当前根目录、相对指针和指纹并完成重新绑定。能够由相对路径和指纹可靠恢复时，不得仅因盘符或父目录变化判定整个快照失效；确实无法重建的具体仓库外指针才进入最小补救。

默认禁止为了“完整”而读取以下内容：完整聊天、旧任务全文、全部 Git 状态路径、完整 worktree 清单、完整 Diff/日志、已关闭轮次原图、历史截图目录或所有附件。出现对应冲突时只展开受影响部分：

- 单写者或旧任务状态冲突：只读取旧任务当前状态和最后一条控制权声明，不读取完整对话；
- 工作区指纹或计数冲突：只列出发生变化的路径；
- 远端基线冲突：只读取受影响引用和对象；
- 证据指针缺失：只回查能判断该缺口的最少清单或附件。

## 4. 紧凑核验输出

工具和回复默认只输出以下聚合字段，不输出长清单：

```text
snapshot: ID / hash / fact_cutoff / valid
rules: root / profile_hash_match / source_hash_match / expanded_rules
writer: registered_generation / observed_old_task_state / conflict
workspace: path / branch / head / staged_count / tracked_count / untracked_count / aggregate_fingerprint
remote: repository / default_ref / head / changed_since_cutoff
runtime: expected_candidate / code_head / canonical_start_command / startup_check / selector_profile / dependency_lock / model_asset_digest / endpoint / pid / served_source / visible_version / status
commit_ledger: last_cutoff / key_node_count / mapping_status
evidence: required_pointers_exist / missing_pointers
diagnosis: active_record / first_deviation / node_coverage / step_deck_pointer_and_hash / evidence_status
operator_profile: unasked / enabled-and-valid / paused / disabled / unavailable / expired；introduction: not-shown / shown / answered / ignored；maintenance: not-triggered / no-new-evidence / updated / review-needed
result: PASS / WARN / FAIL
affected_scope: none / affected items and minimal remedy
```

只有 `WARN` 或 `FAIL` 字段可以触发展开；展开也只限对应项。快照正文采用软目标：优先控制在约 6,000 个中文字符或 12 KB UTF-8 内；若必要事实超过软目标，保留结论和失效条件，把历史、清单及大证据移为稳定指针，不得硬截断安全字段。

## 5. 证据与清理边界

交接不是清理任务。文件存在不会自动进入模型上下文；候选不得为了节省 Token 枚举、打开或删除历史截图。关闭轮次继续登记为 `closed/cold`、`default_read=false`。清理只在项目规则规定的低频触发点形成候选清单，并作为独立任务取得删除授权后执行；没有授权时只给出清单路径和人工操作说明。

## 6. 可切换与失效条件

达到可切换条件必须同时满足：快照有效；核心配置与来源指纹可确认；旧总指挥身份和当前状态可确认；不存在第二个中央写者；目标、断点、工作区、Git/平台基线、耐久 Commit 台账及相关 `KEY_NODE`、目标候选、规范启动命令及自检输出、运行身份、必要证据入口和禁止项可恢复；若当前任务正在进行链路排查，其稳定节点编号、覆盖状态、第一处偏差和必要展示产物指针也可恢复；所有差异已解释或限定为不影响切换的范围。

以下任一情况使候选截点失效：规则或配置指纹变化；中央世代/单写者变化；旧总指挥在候选截点后产生实质调度或中央写入；工作区聚合指纹、Head、远端基线、活动目标或任务断点变化；相关 `KEY_NODE`、提交映射、目标候选、规范启动命令/自检契约、运行入口/选择器、依赖、模型/资产或服务来源变化；必要证据入口消失；发现未核验远端写入、不可逆动作或另一个调度者。

## 7. 统一接管汇报模板

本节是面向操作者的接管汇报格式唯一来源。适用于正常交接、已确认总指挥身份的中断恢复，以及跨账号、跨任务或同一任务内发生的正式换任；普通阶段推进不自动产生新世代。其他入口只引用本节，不维护第二份模板；不符合本配置候选路径的恢复场景只读取本节格式，不因此取得候选资格或调度权。

每次切换尝试结束的那一轮最终回复，固定保留以下四个标题、顺序和字段。AI 自动填写；不适用写“不适用”，不可取得写“待确认”，不能留空、输出未替换占位符或要求操作者填写技术字段。细节按风险增减，不增加无关日志和历史清单。

```text
1. 总指挥身份
当前任务 ID：<平台实际任务 ID；不可得则写待确认及原因>
当前角色与世代：<候选/正式总指挥> / <已核实世代>

2. 交接结论
切换状态：<已完成/未完成>
当前范围交接条件：<已满足/未满足/待确认>；<关键依据，含旧写者状态、中央回读与基线核对>
关键遗漏或阻断：<无；或证据、影响范围及受影响动作>

3. 接续断点
当前目标与阶段：<可恢复的目标和阶段>
已完成与未完成：<有凭证的成果；剩余对象及精确下一步>
恢复基线与证据：<必要的版本/分支/工作区状态及最小证据入口>

4. 下一步与边界
AI 下一步：<当前授权内的具体动作；无可执行事项则明确等待>
操作者下一步：<无需操作；或确需人工完成的最小动作、目的、预期结果和异常反馈方式>
授权与暂停项：<旧授权未继承；当前允许范围、暂停动作及恢复条件>
```

- ID 用于在有访问权限的平台中定位任务，世代编号用于区分写者任期，任务标题仅作显示。不得承诺任意账号或窗口凭 ID 即可跨权限访问；跨宿主联络确需附加路由时，只补平台已核实的信息。真实 ID 仅用于当前对话和获授权的运行时联络，禁止落盘时不得写进仓库文件；公开示例仅用 `<COMMANDER_TASK_ID>`。
- 先按当前目标、单写者、精确断点、必要证据和权限判定条件，再填写结论，不能倒推缺口。没有证据支持遗漏时写“无”；不为填表扫描全部历史、制造问题或强行要求操作者补材料。未知必须写明影响依据，不能自动等同失败或通过；置信度如需说明使用有依据的定性判断，不附无校准的精确概率。
- 条件未满足或待确认时，在第 4 段给出对应最小补救路径和行动方；AI 可在已有授权内核验的事项由 AI 处理。当前恢复必需证据缺失仍阻断受影响切换；历史无关、辅助材料或画像适配问题只暂停依赖动作。正确暂停的远端动作不等同交接失败。
- 接管完成后需要继续工作的，以第 3、4 段恢复原队列，不从头重做已有凭证的成果；没有活动目标时明确等待新的指令，不虚构研发任务。旧授权、进程和专业结论均不继承，报告本身不产生新授权。
