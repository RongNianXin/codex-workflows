# 执行—独立审查协作规范

版本：2026-09-07.1；按需加载，试行。适用于代码、算法、研究策划、资料检索和文稿等有明确交付物的工作。只统一协作程序，不统一专业验收标准，不证明两名 AI 能保证正确。

## 1. 入口与角色

操作者入口是 [01 场景 2F](../01-操作者操作手册.md#场景-2f执行独立审查协作)。本规范配合原业务场景使用，不替代实施、测试、远端或专业门禁。用户要求独立审查时可设置两个专项；普通低风险工作不因此默认拆成两个窗口。

| 角色 | 职责和权利 | 禁止项 |
| --- | --- | --- |
| 操作者 | 目标、授权、重要取舍和必要人工验收 | 不承担技术字段填报或整段聊天搬运 |
| 总指挥 | 共同契约、串行派发、证据回读、争议处理、中央状态和最终汇报 | 不替专业证据下结论，不因审查而扩大授权 |
| 专项执行者 | 在授权内产出成果、自检、逐项回应和修订 | 不宣布自己的独立审查已通过，不修改审查原件 |
| 独立审查员 | 独立核对输入与成果，提出问题和关闭条件，复核修订 | 不接管实现、不修改执行者成果、不伪造反对意见 |

两个专项都向当前总指挥负责，彼此无调度权。窗口命名建议为 `【工作项名称｜专项执行者｜序号】` 与 `【工作项名称｜独立审查员｜序号】`；已有名称只建立角色映射，不为套模板强制改名或重建。

## 2. 共同契约与创建

总指挥先回读既有任务和成果，再生成一份共同契约；技术字段由 AI 填写，无法核验时写待确认。至少包含：逻辑工作项及批次、业务目标、交付物、验收与失败条件、实际基线和输入版本、各自可写范围、证据位置、执行与通信授权、轮次上限、当前阶段、下一行动方和失效条件。

实际总指挥 ID、世代及双方任务 ID 在获授权的运行时消息中准确绑定；公开模板仅保留占位符。允许保存的项目实例以逻辑角色及受控路由指针恢复，不把真实平台标识硬编码到公开仓库。换项目或克隆后重新解析根目录与相对路径。

1. 有适用窗口就复用；角色名相同不证明任务适用，须核对原范围、断点及状态。
2. 只有操作者明确要求创建时才创建独立窗口，使用 `create_thread`，不 Fork 完整历史。算法名称出现在举例或提示词草案中不构成创建授权。
3. 总指挥预填两份角色卡及本阶段提示词，精简共同输入，不复制来源项目的整段聊天。新任务按 03 核对通信握手授权与可达性。
4. 创建、通信、资料处理、产品实施、高资源验证和远端写入分别判定。只有创建/联络授权时停在角色准备，不启动业务。

## 3. 通信和文件责任

默认且本规则仓库采用总指挥串行协调：执行者提交 → 总指挥回读并转交 → 审查员反馈 → 总指挥转交 → 执行者回应/修订 → 总指挥安排复核 → 总指挥收口。两专项不互发消息、不改对方文件。

其他项目历史上存在的直接通信只作为既有实例取证，不能自动迁移。若目标项目明确允许且操作者对当前批次授权，可在该项目实例中指定一次性或有界的直达路由、发送方、接收方、内容、停止点及总指挥回报；本通用模板不授权该例外，也不覆盖仓库禁止专项互联的规则。

消息只通知阶段、版本、文件位置与关键结论；可恢复事实保存在各自允许的本地产物中。执行者提交期间审查对象必须稳定；审查期间实质变化只暂停受影响审查，重新绑定版本。保留原报告和审查依据，修订可采用完整新版本或明确的替换关系，不能让操作者自行拼接不明版本。

工具发送成功不等于对方确认或工作完成。通信失败时不重复派发；总指挥先只读回收，确需人工时给一条准确转交文本。不得自动重建任务、创建后台轮询或定时自动化来绕过联络缺口。

## 4. 阶段、轮次与收口

| 阶段 | 行动方与交付 | 下一步 |
| --- | --- | --- |
| 第1轮产出 | 执行者交初版、自检、证据与未知 | 总指挥核对后通知审查员 |
| 第1轮审查 | 审查员先独立核对共同输入及关键来源，再读作者判断；输出有编号的意见 | 无实质问题可收口；否则安排回应 |
| 第2轮产出 | 执行者逐项回应并提交必要修订；无须修改时说明依据 | 总指挥安排定点复核 |
| 第2轮审查 | 审查员核对原意见和受影响回归，标已解决/部分解决/未解决/撤回 | 总指挥收口或说明第3轮必要性 |
| 第3轮（可选） | 仅处理有实质意义、现有授权与证据可解决的剩余问题，修订后复核 | 达到上限必须停止，保留未决项 |

默认最多两轮，绝对上限三轮；一轮按一个成果版本及其审查计算，不按消息条数。没有问题不凑修改或轮次。一次诊断审查加作者回应而未再独立复核，应记“作者已回应，未再次独立复核”，不能改写为两轮通过。

每条意见包含编号、对象位置、问题类型、证据、影响范围、严重程度和关闭条件。执行者可以接受、部分接受、有证据反驳或保留未知；审查员也可撤回意见。共同输入不足必须单列，两个 AI 的一致不能补出缺失证据。

同类修补连续两次无改善时按项目停止规则重新检查根因；三轮上限不授权继续第三次近似修补。缺数据、缺授权、需要专业签认或目标发生实质变化时提前暂停受影响动作。换人、换窗口不清零轮次；新工作项须由总指挥说明真实范围变化，不能通过改名逃避上限。

总指挥最终分别报告：成果状态、实际验证、独立审查状态、保留风险、人工验收及下一行动方。修改了被审查成果后，旧通过结论只适用于旧版本。文稿认可不等于允许投稿；诊断审查不等于修复效果通过；资料核对不等于专业判断成立。

## 5. 换任、人工反馈与恢复

正式换任严格按 [04 专项联络恢复](../04-状态、目标变更与交接规范.md#正式切换后的专项联络恢复)。需要继续协作的执行者和审查员分别确认新汇报对象、世代、已核验断点和边界；不得用执行者的确认替代审查员确认。仅需历史取证的已完成任务不唤醒；操作者明确要求这组角色继续合作时可仅恢复联络，不重新执行已完成审查。

人工反馈默认发给总指挥。若操作者直接发给执行者，执行者只在当前权限内接收、分析或处理；向用户回复不等于中央收口。有有效回报授权时必须将结果交当前总指挥，无授权则保存产物并说明待转交。总指挥核对反馈对应的输入/版本，判断是否需要本批独立审查；新修复须按契约审查，历史审查不自动覆盖。单纯反馈“看过了”不自动触发代码修改或无关重审。

恢复最小记录：工作项/批次、角色、汇报世代、阶段、当前有效输入与产物版本、问题编号和状态、已用轮次、联络确认、权限依据、下一行动方、失效条件。只回源受影响部分，不继承旧专业结论或旧执行授权。

## 6. AI 阶段提示词模板

以下由总指挥填好再发送，不能把未替换占位符交给操作者。模板文本不是授权本身；权限字段必须有当前真实依据。

### 执行者启动或继续

```text
你是【工作项】的专项执行者。当前总指挥为【实际路由与世代】，共同契约为【已核对的路径与版本】。先读适用规则及契约，核对你自己的既有断点，不继承旧权限。
本阶段是【轮次、阶段】，只交付【成果】；允许【动作与路径】，禁止【边界】。按【验收标准】自检，标明未验证项。收到审查时逐项回应问题编号，只修有据问题，保留原审查和旧版依据。
通信仅允许【实际授权的路由与内容】。完成后向当前总指挥回报有效版本、证据、问题状态及下一步，然后停止。不通知另一专项、不写中央、不自行进入下一阶段。通信失败保存结果并说明，不重复派发。
```

### 审查员启动或继续

```text
你是【工作项】的独立审查员。当前总指挥为【实际路由与世代】，共同契约为【路径与版本】，本阶段为【轮次、阶段】。
首次先独立核对共同输入及关键来源并保存简短判断，再审查【成果版本】。复核阶段只核对【问题编号】及受影响回归，不机械重做初审。
意见写清位置、证据、影响和关闭条件；无有据问题就明确无，不强制反对。只写【审查目录】，不改作者成果，不接管实现。允许的验证为【范围】，其他运行和写入不获授权。
通信仅允许【实际授权的路由与内容】。完成后向当前总指挥回报报告、审查状态和保留项，然后停止，不通知执行者。文件缺失或版本变化时报告具体缺口。
```

### 新总指挥仅恢复联络

```text
本次仅恢复协作联络，不恢复业务执行。操作者已确认总指挥切换，中央已回读：新汇报对象【实际ID】，世代【世代】。你继续担任【角色】，已核验断点为【批次、版本、阶段】。
请只核对自身短状态，确认上述四项（汇报对象、世代、断点、仅联络边界），在允许的自身短状态中登记并向新总指挥回复一次；真实ID不得写入禁止保存它的仓库。你后续收到人工反馈时不能脱离共同工作项自行收口，须按当前回报授权交总指挥安排。
不改产品、不运行测试/模型/服务、不重审、不联系另一专项、不恢复旧授权。存在冲突则只报告差异。本次允许你向上述新总指挥发送该确认；确认后停止。
```

## 7. 适用例与检查

算法工作：执行者提供实现和实际验证；审查员审代码、几何/统计口径与结果边界，必要运行仍单独受资源授权约束。研究策划：执行者提供有来源的方案，审查员核对证据、可行性及夸大，不能把修订文稿当实验成功。资料检索：执行者交筛选结果与来源，审查员核查相关性、时效、反证及遗漏，不能要求无边界全量检索。

交付前用“已有任务换任、新任务启动、无问题提前结束、第二轮仍缺证据、联络失败、人工反馈直达执行者”逐项走读，检查每一步是否有唯一行动方、证据、权限和停止点。这是规则演练，不等于各领域成果或所有宿主通信已经验证。
