# 输入到输出链路排查与算法调优标准

版本：2026-09-02.3

定位：本文件是按需加载的排查与调优手册。它把不可观察的输出异常还原为可检查的实际执行图，通过分层观测和因果实验定位根因，并由 AI 带领操作者理解排查过程。它不是新的编号规则，不产生产品修改、高资源运行、敏感数据采集、专业结论、部署或远端写入授权。

## 1. 目标

本标准解决的不是“怎样多试几个参数”，而是以下四个问题：

1. 同一个输入实际经过了哪些节点、分支和状态变化；
2. 预期与实际从哪里开始出现可靠偏差；
3. 哪个因素对偏差具有可验证的因果作用；
4. 怎样只修改有证据支持的节点，并证明没有把问题转移到别处。

操作者可以只提供日常语言现象。AI 负责恢复技术事实、准备证据、解释因果并维护验证闭环；输入简单不能成为缩短分析、遗漏风险或降低输出质量的理由。

## 2. 适用条件与排除项

命中下列任一条件时使用本标准：

- 算法、模型、页面、接口、数据处理或部署结果不符合预期，根因不明；
- 同一输入在不同设备、环境、版本或入口得到不同结果；
- 结果只在部分样本、边界条件或特定顺序下异常；
- 实际影响范围或执行链路无法从现有证据确定；
- 同一问题连续两次采用近似修补仍未改善；
- 准备调参，但尚未证明问题确实来自参数或目标节点。

以下情况不必机械加载全文：

- 根因已由稳定复现和直接证据确定，修复边界清楚；
- 纯文字、格式、命名等不改变行为的局部任务；
- 只需回答概念问题，不需要定位当前系统异常。

本标准不能替代业务验收、领域专家结论、独立代码 Review、仓库门禁或发布授权。没有可靠真值时，可以定位工程链路中的偏差，不能据此宣称业务、医学、财务或其他专业结论正确。

## 3. 统一术语与证据等级

### 3.1 实际执行图

“链路”是便于交流的简称。真实系统可能包含分支、循环、回退、缓存、重试、异步任务、并发状态和外部服务，因此最终记录应是实际执行图，而不是强行画成直线。

执行图必须来自当前代码、配置、运行状态、日志或可复现实验。设计文档、旧图和历史总结只能作为待验证参考。

### 3.2 第一处可靠偏差

在同一可复现基线下，沿实际执行图比较预期与实际，最早出现且能重复观察到的差异。它用于缩小范围，不自动等于根因。

例如，上游输入已经错误、缓存返回旧值或观测工具本身改变时序，都可能让某个中间节点成为第一处“被看见的”偏差，但真正原因在更早位置或图外依赖。

### 3.3 根因

能够解释异常，并在控制其他关键变量后满足至少一项可证伪证据：

- 只改变该因素，预测的中间量与最终结果按预期变化；
- 移除或恢复该因素，异常可重复消失或重现；
- 独立证据排除了主要竞争假设；
- 无法直接干预时，存在强度与风险相称的等价因果证据，并明确保留限制。

仅有相关性、时间先后、一次成功或“看起来像”不能写成已确认根因。

### 3.4 状态词

- `已确认事实`：由当前代码、配置、Git、日志、测试、平台回执或绑定版本的人工观察支持；
- `合理假设`：能解释现象，但尚未通过可证伪实验；
- `个人偏好`：期望的视觉、交互、性能或业务取舍；
- `待确认事项`：证据缺失或冲突，当前不能可靠归类；
- `已否定假设`：预先定义的预测未出现，或被更强证据反驳。

## 4. 固定排查流程

### 阶段 A：定义失败与验收

1. 固定一个具体问题：输入、正式入口、操作步骤、预期、实际和允许误差。
2. 区分主观不满意、工程契约违反、跨环境不一致和专业正确性争议。
3. 选择至少一个失败样本和一个已知正常对照；若没有正常对照，明确写“待建立”。
4. 写出本轮排除项、资源和权限边界，以及什么证据足以停止排查。

没有明确预期或可比较指标时，先协助操作者建立最小验收定义，不直接开始调参。

### 阶段 B：冻结可复现基线

至少记录：

- 代码版本、分支/worktree、未提交与未跟踪修改；
- 依赖、运行时、设备、后端和关键环境配置；
- 模型、权重、资产、数据与生成物指纹；
- 参数、随机种子、缓存、时间窗口和特征开关；
- 正式入口、操作顺序、输入原始字节或可靠等价标识；
- 当前验证结果及其时间、来源和有效范围。

无法冻结的变量标记为待确认，并判断它是否足以使后续结论失效。来源不明修改先保护，不得为建立基线而自动清理、覆盖、提交或隐藏。

### 阶段 C：还原实际执行图

从正式入口向输出逐层追踪，至少覆盖：

1. 输入获取与解析；
2. 预处理、归一化、裁剪、坐标或单位转换；
3. 核心算法、模型或业务逻辑；
4. 后处理、阈值、筛选、排序或聚合；
5. 状态存储、缓存、序列化和传输；
6. 渲染、导出、展示或下游消费；
7. 条件分支、回退、重试、异步和外部依赖。

对每个节点建立最小契约：

| 字段 | 必须回答的问题 |
| --- | --- |
| 节点与实现位置 | 当前实际执行的是哪段代码、服务或配置 |
| 输入 | 数据、形状、单位、坐标系、范围、版本和来源是什么 |
| 处理 | 关键转换、参数、状态和分支是什么 |
| 输出 | 产生什么数据，交给哪个下游 |
| 不变量 | 正常情况下哪些条件必须成立 |
| 观测证据 | 怎样低成本保存摘要、指纹、统计量或必要样本 |
| 失败信号 | 哪种差异足以说明本节点或上游异常 |

执行图的基础交付使用等宽文本，而不是强制使用宽幅 Mermaid。节点使用稳定的阿拉伯数字编号；同一节点在总览、节点卡、日志、图片文件名、HTML 和 PR 说明中保持同一编号。长链路按阶段纵向分段，不能为了排版省略关键节点。

#### 节点粒度与两层展示

完整性优先于精简，精简优先于实现细节堆叠。AI 必须先建立完整稳定节点清单，再从它派生默认总览，不能为了让图变短而反向删掉真实节点。

1. `完整节点层`：保留所有会改变数据、状态、分支或证据等级的关键节点及稳定编号；它是节点卡、日志和 HTML 的映射基准。
2. `紧凑总览层`：把职责连续、共享同一输入输出语义、没有独立失败门禁，而且合并后不影响定位第一处偏差的相邻节点显示为编号区间，例如 `[05–07] 坐标、尺度与 ROI`。被合并节点仍在完整节点层逐项存在。
3. 软目标是每个阶段约 3～7 个总览块、整条主链约 8～18 个总览块；链路本身更简单或更复杂时可以突破，不能为了凑数量漏项或拆碎。
4. 下列内容默认不得被静默合并：运行版本/profile/实际服务来源；坐标、单位和尺度转换；有损预处理；核心算法或模型调用；阈值、质量和安全门禁；并行分支、重试与回退；缓存、异步失效和外部依赖；状态写入；正式输出或下游消费。
5. 风险区、第一处可靠偏差附近、证据冲突区和操作者点名区间必须展开为完整节点；风险消失后可以恢复紧凑显示，但编号不变。
6. 图默认按阶段自上而下对齐。长回线、重复子流程和共享旧核心用“调用点 + 单独局部图”表达，不跨整屏拉连接线；节点名称只写职责，细节放节点卡。

```text
1 原始输入
↓
2 输入校验与预处理
↓
3 构造检测区域与提示
├─→ 4 局部颜色或纹理证据 ─┐
└─→ 5 几何或边缘证据     ─┴→ 6 候选融合与质量门禁
                                  ├─通过→ 7 输出
                                  └─不可靠→ 8 人工回退 → 7
```

图后必须给出符号说明，并逐节点标记 `已观察 / 仅代码确认 / 待插桩 / 不适用`。文本图负责完整和可复制；Mermaid、SVG 或 Excalidraw 负责需要放大、编辑或理解复杂拓扑的局部视图，不能取代节点证据表。

### 阶段 D：分层观测并定位第一处偏差

1. 先在阶段边界设置低成本观测点，不默认记录全部原始中间产物。
2. 用同一失败样本和正常对照跑通实际入口，确认输入确实到达预期路径。
3. 从输入向输出比较节点契约，找到第一处可重复的偏差区间。
4. 只在该区间附近增加更细观测，避免日志噪声、性能下降和敏感信息扩散。
5. 若偏差随运行漂移，先检查随机性、缓存、并发、时序、资源回退和外部服务，再决定是否扩大样本。

观测证据应优先使用指纹、维度、范围、统计摘要和脱敏差异；只有这些不足以定位时，才保存必要的原始中间产物。

#### 逐链诊断与教学合同

AI 同时承担故障诊断专家和老师的职责，但只展示可核对的诊断路径摘要，不输出冗长的内部思维过程。报告必须从上游到下游逐阶段说明：

1. `为什么查这里`：本阶段可能怎样制造当前现象，或为什么应先排除；
2. `已有证据`：当前代码、配置、运行、失败/正常对照和人工附件分别证明到什么程度，并标出证据状态；
3. `对照结果`：本阶段输入、不变量、输出在成功与失败之间是否一致；
4. `判断边界`：哪些假设被支持、削弱、否定或保留，明确区分事实与推断；
5. `下一项判别观测`：只提出最早、最低成本且能区分竞争假设的一项观测，并说明不同结果会把排查带向哪里。

AI 不得只报告“第一处偏差在节点 X～Y”。若区间跨越多个节点，至少按内部数据变化和门禁把它拆成若干连续小段，说明每段为何仍是候选、当前缺什么证据，以及条件递进的观测阶梯。观测阶梯先核对区间输入和不变量，再观察最早可能分叉的中间量；只有上一层仍一致时才进入下一层，避免一次性加入全链日志、污染时序或把判断负担转给操作者。

到达第一处可靠偏差后，重点展开该区间；其后节点只需说明偏差怎样传播以及为什么它们不可能制造已经在上游出现的异常。附件中的人工观察是定位线索，不自动替代绑定版本、输入和参数的运行证据。

### 阶段 E：验证因果

对第一处偏差附近的每个主要假设，先写出可证伪预测：

```text
假设：如果【因素】是根因，保持其他关键变量不变并执行【单一干预】后，
那么【中间节点】应出现【可测变化】，最终【指标或现象】应出现【可测变化】；
如果没有出现，则该假设被削弱或否定。
```

优先选择以下实验之一：

- 单变量切换或参数回退；
- 同输入、同入口、同环境下的新旧版本对照；
- 绕过缓存、回退或外部依赖后的对照；
- 保存的中间产物在相邻节点间复放；
- 已知正常样本与失败样本的节点级差分；
- 无法直接干预时，使用独立实现、合成输入或不变量验证排除竞争假设。

一次实验改变多个关键变量时，结论只能写成“组合因素相关”，不能分配单一根因。

### 阶段 F：最小修复与算法调优

1. 只修改有因果证据支持的节点、参数或契约。
2. 先修输入、单位、坐标、版本、缓存、状态和分支错误，再考虑调核心算法参数。
3. 参数调优必须明确目标指标、约束指标、样本划分、搜索范围和停止条件，不能用最终展示图的主观观感无限试值。
4. 保留失败前基线和回退方式；不得为单个固定样本写入输入哈希特判或不可泛化的截图补丁。
5. 修改公共契约、数据格式、模型或资产时，重新评估兼容性、责任和授权。

### 阶段 G：回归与收口

至少覆盖：

- 原失败样本：确认问题确实消失；
- 已知正常样本：确认原有正确行为未退化；
- 邻近边界或反例：确认不是把阈值问题移到旁边；
- 独立保留样本：降低针对已见样本过拟合的风险。

收口必须记录：实际执行图、第一处偏差、已确认根因或剩余假设、修改节点、验证证据、未验证项、回滚方式和结论失效条件。需要提交 PR 时，把稳定复现、因果证据和实际验证摘要带入 PR，不复制无关调试流水。

## 5. AI 与操作者的引导式协作

### 5.1 操作者的最小输入

操作者只需提供 AI 无法可靠推断的信息：

- 实际看到的现象；
- 希望的结果或“暂时说不清”；
- 线下操作、业务决定或专业观察；
- 对高资源、敏感数据、产品修改和远端动作的相应授权。

技术路径、版本、命令、日志位置、参数和中间证据由 AI 自动查找并预填。操作者不确定时，不要求其猜测。

### 5.2 每轮引导格式

AI 在要求人工参与前必须先自动准备页面、输入、版本和观察位置，并按以下顺序说明：

1. `本步目的`：正在区分哪两个或哪几种假设；
2. `AI 已准备`：已固定的版本、输入和自动证据；
3. `请观察`：一次只给 1～2 个连续动作和一个明确观察点；
4. `结果含义`：每个选项会支持、削弱或保留哪些假设；
5. `下一步`：不同结果将如何改变观测点或实验。

可直接复制的回答：

```text
1. 符合预期：我看到【可选：简短现象】。
2. 不符合预期：我看到【简短现象】。
3. 不确定，请继续自动核对；如果仍需我观察，请换一种说明或提供对照。
4. 我还没有执行这一步，请保持“未执行”。
```

这些选项是中间证据，不是整项验收。AI 收到反馈后必须说明它改变了什么判断，再给下一步；不得连续索要多张无对应关系的截图。

### 5.3 帮助操作者建立工程理解

每个阶段结束时，AI 用当前操作者能理解的语言说明：

- 输入如何流到输出；
- 当前第一处可靠偏差在哪里；
- 哪些只是相关，哪些已有因果证据；
- 下一项实验为什么能区分竞争假设；
- 修复为什么放在该节点，以及还有哪些未验证边界。
- AI 是怎样沿链路从上游排除到当前定位的；每一步使用了什么证据、保留了什么限制。

随后让操作者选择：`已理解 / 需要换一种解释 / 仍不确定 / 不适用`。该状态只用于调整解释方式，不是能力评分，不得代替代码、算法、业务或专业验收。

首次交付执行图、每个阶段报告和最终诊断报告结束时，AI 还必须询问：`是否需要生成或更新按同一节点编号的可翻页 HTML 详细解释？` 普通进度消息不重复询问。操作者选择需要后才生成；选择不需要不影响技术排查。

## 6. 分层展示与 HTML 步骤演示

### 6.1 展示层级

展示形式按实际阅读需求逐级增加，不要求操作者先知道工具名称：

1. `基础层`：默认交付紧凑文本执行图、节点白话卡和证据状态。所有场景都必须可用。
2. `结构层`：需要放大分支、编辑或团队评审时，生成 Mermaid、SVG 或 Excalidraw；节点编号必须与基础层一致。
3. `演示层`：操作者确认需要逐步讲解、逐页对照中间结果或团队演示材料时，生成本地静态 HTML 步骤演示。AI 必须按上一节主动询问，不能等操作者猜到这个选项。

不因生成了更精美的展示而提高证据等级。文本、矢量图和 HTML 都是同一实际执行图的视图，不是三套事实源。

### 6.2 HTML 页面合同

优先复用 [链路分步演示 HTML 模板](../templates/PIPELINE_STEP_DECK_TEMPLATE.html)。默认生成单个可离线打开的 HTML 和相对路径资产；不依赖 CDN、在线字体、遥测或外部脚本。每页只显示一个节点，至少包含：

- 稳定节点编号、阶段和节点名称；
- 证据状态及其含义；
- 输入、实际处理、输出和下游去向；
- 不变量、失败信号、与当前异常的关系；
- 证据来源、绑定基线、生成时间或事实截点；
- 上一步、下一步、左右方向键、步骤计数、阶段索引和查看全部。

步骤较多时，逐步模式只渲染当前节点；“查看全部”按阶段分组并延迟加载图片。超过单个文件适合承载的体积时，保留统一入口和索引，把图片等大资产放到同级目录，不把几十张原图强行转成 Base64 塞进 HTML。

### 6.3 证据区适配

| 任务类型 | 优先展示 | 缺失时怎样写 |
| --- | --- | --- |
| 图像、视频、图形处理 | 同一输入、尺寸、ROI、色标和参数下的真实中间图、叠加图或差异图 | `待插桩 / 未生成`，说明取得该产物需要的动作和门禁 |
| 数据与指标流水线 | 表格、分布、关键统计、单位、样本量和阈值 | `统计口径待确认`，不补造数字 |
| 前后端与接口 | 请求/响应摘要、状态转移、缓存键、时序或 DOM 截图 | `运行证据缺失`，区分代码契约与实际请求 |
| 代码与配置 | 精确差异、配置解析结果、选择器和实际加载值 | `仅代码确认`，不声称已运行 |
| 音频、时序或模型 | 波形/频谱、逐阶段张量摘要、日志、指标或可复放片段 | 写明隐私、体积和高资源边界 |
| 无天然可视产物 | 日志、表格、代码、JSON、文字证据或明确占位 | 不为“每页必须有图”而生成装饰图片 |

示意图、教学图和占位图必须醒目标为 `示意，不是运行证据`。AI 不得根据源代码描述伪造一张“处理后效果图”，也不得把不同输入、不同版本或不同参数的旧图放到当前节点。

### 6.4 生成与验证

1. 先完成实际执行图和节点证据表，再生成 HTML；不能从页面布局反向猜测链路。
2. 默认只把已经获准处理的最小证据写入产物。个人数据、内部路径、凭据、真实账号和受限素材按项目隐私规则脱敏或留在本地受控位置。
3. 动态内容使用安全文本写入，不直接把日志、文件名、JSON 或用户输入拼接为可执行 HTML；本地模板拒绝外部脚本和网络依赖。
4. 生成后必须实际打开并回读：上一页/下一页、左右方向键、首尾禁用、步骤计数、阶段索引、查看全部、窄屏布局、图片缺失提示和无脚本提示。
5. 核对每个 HTML 节点都能映射回文本图和节点卡；证据来源、基线、状态或节点数量变化时，旧演示标记为失效并重新生成受影响页。
6. HTML 通常比重新排版演示文稿更适合快速迭代，但总成本取决于页数、证据生成和验证深度；不得承诺它在所有任务中一定更快或更省 Token。

### 6.5 诊断报告收口与下一步提示词

阶段或整轮诊断报告不能只询问操作者是否看懂。结尾至少包含：

1. 推荐的下一步及其目的；
2. 为什么它是当前最小充分动作，而不是盲目调参、末端补丁或无边界全量观测；
3. 需要的精确授权、资源等级和明确排除项；
4. 预期产物、不同结果的解释、停止条件和结论失效条件；
5. 一段根据当前项目、基线、样本、节点和门禁完整预填、可直接复制发送的“建议下一步提示词”。

这段提示词是当前报告生成的情境化后续建议，不是新的固定操作者入口。`01-操作者操作手册.md` 仍是唯一日常入口；只有操作者重新发送建议文本后，它才构成新指令。提示词必须把已知技术值自动填好，不让操作者补内部 ID、路径、命令或参数；也不得把报告建议、既往授权或“继续排查”扩大解释为产品修改、高资源运行、敏感数据、专业结论、部署或远端写入授权。

## 7. 常见系统的节点映射

| 系统类型 | 常见执行图节点 |
| --- | --- |
| 模型推理 | 原始输入 → 解码/裁剪 → 归一化/张量 → 模型与权重 → 后处理 → 业务映射 → 展示 |
| 传统算法 | 原始数据 → 坐标/单位转换 → 特征或几何计算 → 阈值/约束 → 候选筛选 → 输出 |
| 页面与接口 | 用户操作 → 前端状态 → 请求序列化 → API → 业务逻辑 → 存储/缓存 → 响应 → 渲染 |
| 数据流水线 | 来源 → 采集 → 清洗 → 变换 → 合并 → 质量门禁 → 导出/消费 |
| 部署 | 构建输入 → 构建产物 → 发布配置 → 运行环境 → 网络/权限 → 服务响应 → 客户端展示 |

## 8. 对抗式检查与边界条件

开始前和修复后各检查一次：

1. **路径真实性**：测试和人工观察是否走正式入口，而不是实验页、缓存产物或替代实现；
2. **因果混淆**：是否把第一处偏差、时间先后、相关性或单次成功误写成根因；
3. **非确定性**：随机模型、网络和并发过程是否固定可控条件、重复运行并使用分布或容差；
4. **观察者效应**：日志、调试模式或插桩是否改变时序、性能、内存或执行分支；
5. **样本泄漏**：调优样本是否同时被当作独立验收样本，是否只对固定输入有效；
6. **隐藏状态**：缓存、特征开关、账号、权限、时区、编码、设备后端和外部服务是否进入基线；
7. **隐私与安全**：中间图像、用户输入、日志和模型输出是否含敏感信息，证据是否最小化并留在受控位置；
8. **资源与费用**：是否错误地把批量推理、多浏览器、真实媒体或外部付费服务当作普通低风险检查；
9. **验收边界**：工程一致性是否被误写成业务、临床、合规或其他专业正确性；
10. **回归范围**：是否只修复原样本，却破坏正常样本、边界样本、性能或兼容性。

发现问题时按“阻断问题 / 建议修复 / 可接受风险”报告，只暂停实际受影响的动作。当前没有证据支持新增问题时停止审查，不为完整感虚构风险或无限扩展验证。

## 10. AI 内部质量检查清单（不是操作者提示词）

操作者日常只从 `01-操作者操作手册.md` 的场景 2C 进入；本标准不再发布第二份平行的通用提示词。AI 输出报告前检查：

1. 实际运行版本、入口、配置、模型和资产是否有当前证据；
2. 紧凑总览是否能映射回完整稳定节点，关键分支和风险区是否展开；
3. 是否沿链路给出了证据化诊断路径，而不只是一个节点范围或无依据猜测；
4. 第一处偏差、根因、人工理解和技术验收是否保持不同状态；
5. 是否主动询问可翻页 HTML，并在生成后实际核对；
6. 是否给出最小下一步和完整预填的情境化后续提示词，同时保留所有授权门禁。
