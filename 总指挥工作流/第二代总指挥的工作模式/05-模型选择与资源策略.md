# 模型选择与资源策略

## 1. 默认配置

默认沿用使用者已选定且当前适用的模型、推理强度和速度，不因任务切换或模型发布逐轮重选。尚未选择时，以客户端当前可用的适用默认配置为起点；具体型号与档位不写成长期固定要求。已有明确选择属于当前配置依据，不应被本节自动降档；快速模式、极高推理或额外费用仍须符合已有授权，没有授权不得启用。

运行时可用型号、API 文档支持项、客户端界面和账号权限必须分别核对；不能从其中一个推定其他能力。无法回读实际配置时标记“待确认”，不假装已经切换。

## 2. 何时评估调整

只在使用者要求选型、工作阶段复杂度明显变化、排除输入与执行问题后仍持续达不到质量要求，或后续出现大批量低风险工作时，评估剩余工作的调整收益。不要求复杂任务先低档试错，不因一次工具或网络失败就归因于模型。

| 当前证据 | 可考虑的方向 | 比较依据 |
|---|---|---|
| 配置适用，当前验收稳定通过 | 继续当前配置 | 不增加切换、取证或人工成本 |
| 关键推理仍失败且已排除输入、环境与执行错误 | 更合适的能力或推理强度 | 代表性难例的正确率、返工与失败代价 |
| 后续为大量可重复验证的低风险操作 | 较低成本配置的小范围比较 | 同一验收标准下的质量、总耗时与可见费用 |

此表只在触发评估时使用，不作为每回合必须执行的选型表。没有明确收益时继续已适用的配置。

## 3. 选择与执行边界

1. 比较完成剩余目标的总成本，计入读取、推理、返工、验证、切换和人工操作；单次 Token 价格、推理档位名称或基准最高成绩不能替代本任务结果。
2. 跨模型同名推理档位不视为固定等价；“统一降低一级”“某型号中档永久默认”只能是待验证假设。API 价格不能直接换算为 ChatGPT 订阅额度；API 的中途调参能力不等于客户端当前具备可调用的切换接口。
3. 确需比较时，复用当前任务已有的代表性样例与验收；未授权费用或高资源动作先暂停对应实验，不为了选型重新跑整个项目。没有测量数据不声称精确收益。
4. 有实质收益时简短说明理由、影响范围和调整方式；无新证据不重复提醒。能可靠完成的工作继续推进，建议切换不构成全局暂停。
5. 实际调整必须同时符合平台能力与已有授权，并回读生效结果。无法程序化设置时，仅在确需调整时提供一次具体人工步骤；建议配置与实际配置分开记录。专项任务不得自行升级，按已有协作边界回报。
6. 默认只保留主执行窗口的一个模型上下文。例外专项任务仍先通过总 Token 净收益门禁；用户未指定其配置时沿用已适用默认，不为一次选型额外创建任务。

## 4. 配置回报与时效

只在确有调整建议、执行调整或需要人工选择时，简短说明“当前配置（已回读/待确认）、建议与理由、动作和生效结果”；不逐轮比较、搜索或重复报告。复用现有任务记录，不另建选型评分表或周期台账；技术字段由 AI 自动取得。

模型名称、可用档位、价格和迁移能力在决策时查官方资料，并标明核对日期、产品范围与未验证项；按 06 的“按需时效核验与退役”处理过时内容，不周期联网。官方资料说明通用能力，本项目收益仍需要任务证据。

事实入口：[OpenAI 模型目录](https://developers.openai.com/api/docs/models)、[模型迁移与使用指导](https://developers.openai.com/api/docs/guides/latest-model)、[API 价格](https://developers.openai.com/api/docs/pricing)。2026-09-05 核对的迁移指导支持保留原有效推理强度再比较，不支持跨模型档位的固定等价表；后续使用时按实际目标模型重新核验。

## 5. Token 与成本控制

- 成本口径是整个工作流：总指挥输入/输出、例外任务固定规则与证据载入、派发、等待、回执、再汇总、失败重试和人工转发都要计算，不能只观察主窗口。
- “专项任务让总指挥上下文变短”不自动等于省 Token。若专项任务必须重读同一代码、规则、Issue/PR 和人工反馈，通常应留在主窗口；净收益无法确认时也不拆分。
- 使用者默认只向总指挥输入一次。任何要求使用者把同一问题发给两个窗口、把专项结果再贴回总指挥的方案，都应视为额外成本并优先取消；确因平台限制必须人工转交时，只传递最小结果卡或稳定路径。
- 优先减少重复读取和重复回执，而不是盲目降低模型能力。
- 高复杂度任务优先由总指挥一次完成可靠的局部分析与实现；只有独立并行、独立审查、证据隔离或能力缺口有明确净收益时才分派。
- 复盘统计主窗口与专项任务合计 Token 代理指标：载入字节、任务卡数量、工具调用轮次、重复读取、交接/回执次数、失败重试和人工介入。没有请求级账单时不虚构精确 Token 节省比例。
- 未经使用者本人同意，不通过无限循环、定时唤醒或快速模式换取自动化程度。
- 平台 Auto-review 会增加额外模型调用；只有它能明显减少人工等待时才启用，不把它用于本来就在沙箱内可直接执行的动作。

### 5.1 缓存、长上下文与图片

- `缓存命中 Token` 表示服务端识别并复用了可缓存的输入前缀，不等于模型新生成了同样数量的内容，也不等于这些输入从上下文规模中消失。不同提供商的计费、展示和缓存期限可能不同；无法回读账单口径时标记“待确认”。
- 正常优化目标是“双目标”：不可避免且稳定的规则/前缀尽量命中缓存，同时把总输入和缓存输入的绝对规模都控制在解决当前任务所需的最小范围。高命中率配合巨大绝对输入仍可能意味着会话过长；为让缓存数字变小而故意破坏稳定前缀同样没有价值。
- 复盘至少分开看普通输入、缓存输入、缓存创建（平台提供时）、输出、费用、延迟和失败；不得只凭命中率、单张趋势图或估算价格断言任务高效或断连根因。
- 大图和高细节图片可能增加输入 Token 与延迟。人工核验优先逐阶段记录结构化结论，只有异常、关键边界、前后对照或结论冲突才读取/保留原图；通过项通常只保存文字状态和必要定位。
- 长会话会累积重复提示、工具结果和已上传附件。规则可以阻止后续再次打开本地附件，但不能从当前聊天删除既有消息或图片；图片密集的大轮次形成可靠摘要和断点后，先比较继续主窗口与切换任务的总成本，只有净收益明确时才切换，不按每个小步骤频繁换窗。
- 压缩优化必须区分“压缩前输入边界”和“压缩后文件回读门禁”。已经在长寿命总指挥聊天中的图片，事后把本地索引设为冷并不能保证它不再参与平台对该聊天的上下文整理；大量原图确会形成长期负担且结果卡足以支撑后续工作时，可以在图片进入前把一个大轮次放入独立视觉观察任务。少量截图或必须和当前实现连续对照时保留在主窗口。
- 视觉隔离减少的是总指挥后续反复承载原图的风险，不消除观察任务首次读取图片的 Token 与延迟。总览/构图可使用较低细节时只读一次；涉及小字、线宽、端点、颜色、折角、自交或像素级差异时使用最少局部原始细节，不做全局强制降采样，也不重复打开不影响结论的整图。
- 官方压缩资料可以支持“压缩基于既有上下文并生成更小的后续窗口”，但 Codex Desktop 是否在每次压缩重新视觉编码全部历史图片、服务商如何统计缓存/压缩图片、以及它和中转断连的因果关系均为待确认。没有请求级日志时不得给出精确节省比例或单因结论。
- 上下文长度与网络或中转断连可能相关，但没有请求日志、错误码和服务端证据时只能标记为风险因素，不能写成已确认根因。无论根因是否成立，缩短输入、减少大附件重读和保存可恢复断点都具有独立收益。

事实边界参考：[OpenAI Compaction 指南](https://developers.openai.com/api/docs/guides/compaction)、[OpenAI 模型使用指导](https://developers.openai.com/api/docs/guides/latest-model)。它们用于支持压缩和图片输入的一般事实，不替代 Codex Desktop 或当前中转服务的请求级证据。

### 5.2 本地会话日志健康与换任务软门禁

自动上下文压缩与人工换任务解决不同问题：自动压缩在当前模型/配置的阈值附近缩小后续活动上下文，让同一任务继续运行；本地会话日志保存更完整的任务历史，通常不会因自动压缩而同步缩小。同一任务多次自动压缩是正常现象。压缩次数、压缩前 Token 峰值和本地日志大小都不能单独证明异常、费用增加或必须交接。

总指挥在任务启动、稳定里程碑结束、新大型独立波次开始前、图片或大型工具输出密集步骤前后，以及准备交接时，执行一次低成本检查：

1. 优先读取运行时提供的任务 ID 或会话 ID，据此在当前 Codex 本地存储中定位唯一活动会话文件；只读取文件元数据和必要的尾部统计，不为计算大小解析完整 JSONL，也不扫描整块磁盘。
2. 向使用者回报当前文件路径、字节数与 MiB、检查时间和软门禁状态。平台未暴露 ID、文件不存在或无法唯一定位时标记“待确认”，不得伪造路径。
3. 默认小于 `200 MiB` 时不因文件大小改变任务路由；达到 `200 MiB` 时进入“交接评估”，检查稳定截点、当前原子步骤、下一波次和迁移回执，允许有理由地继续当前任务。
4. 达到 `300 MiB` 时进入“优先交接”：不再启动新的无关 Goal、大型独立波次或批量图片输入；先完成或安全停止当前原子步骤，核对结果未知的工具/远端动作，保存稳定截点和精简交接，再建议使用者启动新总指挥任务。没有稳定截点时先补齐截点，不能仅因越线强制中断。
5. `200/300 MiB` 是本工作流基于本地稳定性和恢复成本设置的默认软门禁，不是 OpenAI 官方限制。项目可以根据真实故障和验证结果在实例规则中收紧或调整，但不得静默把软门禁改成自动归档、自动删除或远端动作授权。

禁止使用 `50%/65%/75%` 等固定上下文窗口占比、自动压缩次数或压缩前 Token 峰值作为人工换任务硬门禁；它们会在正常压缩周期中反复出现。平台能够回读请求级统计时，可以把压缩后的活动上下文、普通输入、缓存输入、输出、延迟和失败作为诊断证据，但必须与本地文件大小分开记录。

需要自动提醒时，优先使用只读本地脚本或操作系统计划任务扫描最近活动会话，并只在跨越软门禁时通知；不得为了监控会话大小启动定时模型任务、高频轮询、重复全量解析或持续写详细日志。自动提醒只提供信号，最终交接仍受稳定截点和单写者门禁约束。

### 5.3 额度中断保护与平台 Goal

`/goal` 适合目标、约束、验证和停止条件明确的长任务。它让 Codex 在同一任务中围绕持久目标连续工作，并支持暂停或恢复；它不会增加账号额度、扩大授权、保证任务不会因额度耗尽停止，也不会把原任务状态自动迁移到另一个账号。官方能力边界参考：[OpenAI 持续推进目标](https://learn.chatgpt.com/zh-Hans/use-cases/follow-goals)。

额度中断保护是现有热快照的可选运行策略，不是新的状态系统：

1. 只有使用者明确说明账号额度偏低、要求开启额度保护，或平台给出可观察的用量预警/耗尽信号时启用。平台没有提供剩余额度回读时标记“待确认”，不得根据会话长度、Token 统计或主观体感估算余额、轮次或剩余时长。
2. 新增长任务时，先把目标、排除项、验收和停止条件写入当前角色已有的 Goal、计划、专项短状态或项目进度视图；使用者显式启用 `/goal` 时，将其登记为运行容器。未使用 `/goal` 不影响额度保护和场景 6B 的任务中断恢复，不能为补配置而打断正在安全推进的任务。
3. 长批次开始前先确认当前任务适用的记录已经保存起始基线、批次顺序、首个动作和禁止项；普通任务不强制创建中央状态，专项任务不写总指挥热快照。随后按可独立验证的里程碑推进，只在里程碑、恢复意义变化或额度预警时更新，不为每个命令写状态。
4. 出现额度预警后，不再启动新的长批次、高资源验证或难以在中途判定结果的外部动作；先完成或安全停止当前原子步骤，回读已经发出的远端/不可逆动作，把每项标为已完成、未开始或结果未知，再原子更新并回读热快照。无法安全收口时保留上一可靠截点，并明确当前工作区与结果未知项。
5. 额度已经耗尽且旧任务不可继续时，新账号按 `01` 场景 6B 和 `04` 的通用任务中断恢复继续。新窗口先保持原任务身份，并在读取长历史前比较恢复与安全重做成本；简单且没有可复用成果或外部副作用的任务可以直接重做。需要恢复时，普通任务复用已有消息、计划和产物，专项任务复用任务卡与短状态；只有原窗口本来就是总指挥时，才从项目入口、项目恢复热快照、索引、Git/工作区和必要平台事实恢复中央控制面。对话摘录是可选证据，不继承其中的远端/费用授权、运行中进程、完成声明或专业结论。
6. 不建立常驻模型任务、高频轮询或账号自动切换来“抢救额度”。只有平台或本地工具提供低成本、只读且可靠的用量信号时，才可作为提醒源；提醒不能替代稳定截点或被解释为规避平台限额。

如果当前 Codex 命令列表没有 `/goal`，可以继续使用普通任务和上述热快照机制；是否启用 `features.goals` 应按当前官方文档与客户端能力单独核验，不是本方案的恢复前置条件。

## 6. 长任务低干扰运行

目的：在允许任务耗时增加的前提下，优先保持使用者本人可以继续编辑文档、浏览网页和处理其他本地工作。资源保护依靠可执行的命令级限载，不承诺 AI 无法持续保证的 CPU、内存或 GPU 百分比。

### 6.1 能力边界

- 不建立“CPU 或内存始终低于某个百分比”的运行保证，也不为满足该保证启动专门 Agent、高频轮询、常驻采样器或详细监控日志。
- 必要时可以在重型阶段开始前、出现明显卡顿或诊断异常后执行一次轻量系统查询；查询只提供当时的诊断快照，不代表后续资源上限，也不能替代命令级限载。
- “后台运行”或“无头浏览器”只表示不抢占前台窗口，不等于低 CPU、低内存或低 GPU；它必须与单 worker、重型步骤串行和及时回收进程同时使用。
- 不擅自结束使用者本人、系统或来源不明的进程。只能管理本工作流创建且归属已核实的浏览器、测试、构建、模型或开发服务进程。

### 6.2 默认低干扰策略

1. 同一时间最多运行一个重型步骤。完整测试、生产构建、依赖安装、大型生成器、模型推理、媒体处理、真实浏览器、GPU/Canvas/WebGL 验证和多进程测试都属于重型步骤；它们不得彼此并行，也不得因分属不同 worktree 或任务就叠加执行。
2. 轻量只读查询、窄范围静态检查和不写同一产物的定点测试只有在不会与重型步骤争用资源时才可有限并行。不能确认资源特征时按串行处理。
3. 验证遵循“最小相关检查 → 受影响测试 → 必要时完整套件”的顺序。完整套件只在发布候选、共享高风险改动、仓库明确要求或定向证据不足时运行一次；输入、代码、配置和测试环境均未变化时不得重复全量运行。
4. `npm ci`、重新安装模型或重新下载浏览器只在依赖缺失、锁文件变化、环境损坏或验收明确要求时执行，不把安装步骤机械加入每轮任务。
5. 一次重型步骤失败后先分类为产品代码、测试脚本、命令上下文或运行环境问题；未经实质调整，不立即并行或全量重跑。

### 6.3 浏览器自动化：无头优先与前台控制升级

- 自动回归默认使用无头模式。Playwright 本地运行默认显式限制为单 worker，例如 `--workers=1`；即使仓库配置为 `fullyParallel`，也优先用命令行覆盖，除非使用者本人明确选择速度优先且当前机器资源已经单独评估。
- 浏览器、模型、WebGL、Canvas、视频或摄像头验证不得与 build、完整测试或另一个浏览器验证并行。真实浏览器验证默认最多一次正常尝试和一次有实质变化的诊断尝试。
- 能通过无头截图、DOM、日志、像素、网络请求或结构化状态获得同等工程证据时，不打开或控制可见窗口。页面导航、键盘操作、响应式布局和静态 HTML 导航核对默认也先用无头单 worker 完成，并把截图或报告保存为可回读产物。
- 无头不能替代操作者本人的主观视觉判断，也可能无法覆盖原生桌面、系统弹窗、跨应用拖放、真实账号会话、硬件设备或操作系统权限流程。只有这些缺口会实质影响结论时，才升级为单一可见浏览器、Chrome 控制或 Computer Use；工具能力不足本身只阻断依赖该证据的步骤，不把其他只读或无头检查升级为全局阻断。
- 前台控制按 `09-自动化授权与风险分级.md` 取得当前精确授权。制卡或启动前能够预见时，先写明无头缺口、拟用工具、范围、预计持续时间、对前台办公的影响和关闭方式；运行中才发现时，暂停受影响步骤并请求授权，不得以非阻断通知代替确认。使用者在当前指令中已经明确要求“打开”或“展示”指定产物时，只视为该产物限定可见展示的授权，不延伸为现有浏览器会话控制或 Computer Use 授权。
- 获得授权后默认只开一个窗口和一个上下文，不主动接管已有个人浏览器会话；验证结束立即关闭，不把可见窗口留作后台等待。未获授权时保留无头证据、明确尚缺结论，并继续不依赖前台控制的工作。
- 若已授权的可见窗口同时涉及摄像头、麦克风、登录账号、敏感数据、远端写入或其他原本需要确认的动作，仍按对应独立门禁处理；前台控制授权不得扩大为这些相邻权限。
- Computer Use、Chrome 控制、应用内浏览器和 Playwright 必须按实际调用如实说明；不能把一种工具的弹窗或资源消耗归因给另一种工具。

### 6.4 开发服务与进程回收

- 开发服务只在功能必须通过服务器运行或使用者本人正在人工试用时启动。启动后记录精确目录、端口和归属。
- 每轮修改项目代码并准备交给使用者人工查看时，重新核对服务仍绑定正确 worktree、最新代码和可访问端口，发送本轮有效的可点击 localhost；不得假定上一轮地址或旧进程仍有效。
- 使用者本人明确要继续试用时，可以保留服务并告知 URL；否则自动验证和截图完成后关闭本工作流创建的服务。不得因“可能还会用”长期保留高占用服务。
- 阶段结束、任务暂停或异常退出前，检查本工作流创建的可见浏览器、测试 runner 和开发服务是否仍有用途；无用途时安全关闭。忽略的测试产物可以保留，但不得把残留进程当作交付物。

### 6.5 卡顿与异常处理

- 一旦使用者本人报告卡顿，或出现 GPU stall、浏览器上下文关闭超时、大面积无关测试超时、trace/压缩损坏等资源竞争信号，立即停止启动新的重型步骤。
- 先保存当前命令结果和可恢复断点，再关闭本工作流创建且已确认空闲的可见浏览器、测试 runner 或开发服务。当前步骤可安全中止时停止；涉及结果未知的远端写入时不得直接终止后重试，必须先回读远端状态。
- 后续验证降为单 worker、单命令串行和最小相关范围。若低干扰模式仍复现系统卡顿，暂停本地重型验证，明确未验证项，并把完整测试留给使用者明确安排的空闲时段或已授权的远端 CI。
- 复盘只记录重型命令、并发数、前台窗口、异常信号、降载动作和结果；没有系统级证据时只能写“高度相关”或“待确认”，不得把资源争用直接宣称为操作系统死锁。

低干扰策略只控制本工作流的资源行为，不能替代依赖、文件冲突、风险、隐私和远端授权判断。
