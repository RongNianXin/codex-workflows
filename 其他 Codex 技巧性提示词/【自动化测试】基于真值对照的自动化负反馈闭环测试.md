请按以下规则自动执行：

一、开始前

1. 读取项目规则、相关代码、已有测试和验证材料，确认当前工作区、基线版本、未提交修改以及真实产品入口。

2. 从当前对话中判断测试对象。只有完全无法判断，而且不同理解会明显改变测试结果时，才允许向我追问一次。

3. 区分已确认事实、合理假设和待确认事项，从测试目标、质量标准、数据和现有实现中确定最小可验证方案。

4. 自动把我填写的质量标准转换成可以检查的验收条件：

   - 有人工标注、参考结果或已有标准时，优先使用；
   - 能量化时，自行选择合适指标，不要要求我填写专业参数；
   - 不能完全量化时，结合结果截图、叠加图、输出文件或实际页面进行审查；
   - 没有可靠参照时，可以建立本轮使用的临时评价规则，但必须说明依据和局限，不得冒充正式行业、业务或专业标准；
   - “不得遗漏”“不能出现”“必须全部”等表述属于逐个样本的硬性要求，不能用平均结果掩盖失败样本。

5. 简要说明准备如何判断结果是否合格，然后直接开始，不要输出冗长计划或思维链。

二、轮次与时间

1. 如果停止条件写的是“最多进行N轮测试”，首次基线测试计为第1轮。

2. 如果明确写的是“最多进行N轮优化”或“N轮修改”，首次基线测试不计入优化轮数。

3. 如果同时设置轮数和时长，以最先达到的条件为准；达到质量要求时可以提前停止。

4. 一轮有效测试是指：完成规定数据的测试，并产生可以与质量标准比较的有效结果。

5. 测试脚本、依赖、环境、坐标、单位或评价方式发生故障时，本次不算有效测试轮次；修复后重新运行当前轮，但消耗的执行时间仍计入总时长。

6. 总时长从正式开始执行测试时计算；等待用户进行必要授权的时间不计入执行时长。

三、负反馈闭环

每轮按照以下方式执行：

1. 使用相同的数据、入口、关键参数和可复现条件运行测试。

2. 检查数据来源中的全部文件。每个文件都必须被测试，或者记录无法测试、格式不支持、不属于测试范围等明确原因，不得静默跳过失败数据。

3. 将实际结果与质量标准、人工标注、参考目标或临时评价规则比较。不得仅因为命令成功、页面没有报错、生成了结果或结果非空，就判定质量合格。

4. 判断问题来自算法或产品逻辑、测试证据、测试数据、运行环境，还是权限和安全限制。

5. 如果属于算法或产品逻辑问题，根据当前证据进行一组范围最小、可以解释的调整；如果属于测试工具或环境问题，先修复测试证据链，再重新运行当前轮。

6. 修改后重新测试，并检查是否破坏原本正常的功能、其他有效样本或既有使用流程。

7. 比较当前结果与基线及当前最佳结果。效果变差时，不继续叠加近似补丁；只撤回本轮产生的退化改动，保留当前最佳方案，不得覆盖用户原有修改。

8. 每轮保留必要的内部记录和结果证据，但不要逐轮向我输出完整报告。只有需要人工授权、发生阻断或任务持续较长时，才进行简短说明。

四、可信度要求

不得通过以下方式制造“测试通过”：

1. 降低、偷换或模糊我填写的质量标准；
2. 修改人工标注、参考结果或测试数据来迎合算法；
3. 删除、隐藏、静默跳过失败样本，或者只展示效果好的结果；
4. 针对文件名、路径、文件哈希或固定样本编写特殊判断；
5. 把执行成功、结果非空或少量样本通过，当成整体质量合格。

如果数据量足够，可以自动保留部分数据用于最终复核，不要使用这部分数据反复调整算法。数据太少或全部数据都参与了调整时，可以继续测试，但最终必须说明结论只适用于当前数据，泛化能力尚未验证。

五、停止与权限

满足以下任一条件时停止：

1. 达到我填写的轮数门限；
2. 达到我填写的时间门限；
3. 已经满足全部质量标准；
4. 连续两轮有效调整没有改善，重新检查根因后仍没有新的证据支持继续修改；
5. 继续修改只能依靠降低标准、修改参考结果、硬编码或扩大未授权范围；
6. 出现无法自行解决的安全、权限、资源或环境阻断。

停止时保留证据支持的最佳方案，不机械保留最后一次修改。

默认只允许当前任务范围内的本地修改和测试。不得覆盖用户已有修改，也不得擅自提交、推送、部署、触发远端任务、上传敏感数据或修改受保护功能。需要高资源测试、远端操作或其他人工授权时，只暂停对应步骤并说明原因，其他不受影响的工作继续进行。

六、最终输出

停止后只输出一次最终结果，不展开每轮中间过程。使用普通人能理解的语言，回答以下五项：

1. 触发了什么停止条件；
2. 测试结果是什么，包括有效数据数量、成功情况、失败或遗漏情况以及最重要的结果证据；
3. 当前功能或算法做了哪些修改，与测试前相比发生了什么变化；
4. 根据我填写的质量标准，当前结果属于“符合预期”“不符合预期”还是“证据不足，无法确定”，并说明主要依据和剩余风险；
5. 下一步最小计划建议是什么，包括仍需解决的问题和尚未验证的范围。

最终结果必须以真实执行证据为依据。未运行的测试要明确写“未运行”，不能表述为“已验证”；没有达到质量标准时，不得使用“基本通过”“大致可用”等模糊说法代替真实结论。

不要输出冗长思维链，只提供最终结论、关键依据、结果证据、风险和下一步。
